# MCP 接口变更即时回显

Status: needs-info
Date: 2026-11-01
Feature: mcp-client-sync

## 目标

MCP 修改接口成功后，客户端在原标签内显示最新内容，并给出可辨认的更新反馈。用户不需要关闭重开标签；有本地编辑时保护内容并明确呈现待处理更新。

## 已验证的代码事实

- MCP 的 `callTool` 调用工具并返回结果，没有向客户端发送 Target 变更通知；`src/main/mcp/server.ts` 只向 MCP 调用方返回结果。
- `src/preload/index.ts` 的 Target API 只有调用接口，没有变更订阅。现成的订阅和窗口广播模式分别见 `subscribe` 与 `src/main/mqtt/events.ts`。
- `src/renderer/src/store.ts` 的 `openTarget` 对已经打开的接口仅修改 `activeId`；`reloadTargets` 仅刷新树列表，不更新 `drafts` 或标签标题。
- 保存接口的 `saveTarget` 当前提交整份草稿，没有与已保存内容比较的并发检查；保留旧草稿后直接保存，会覆盖 MCP 刚写入的内容。
- 普通字段主要由草稿受控显示，更新同一 ID 的草稿能够回显。字段规则、接口说明弹窗和部分失焦才提交的表格输入另有本地状态，尚未提交时不进入标签的 `dirty` 状态，必须另行保护。
- 存储层不能只覆盖 `saveTarget`：删除、递归删除目录、重排/移动，以及仅更新用例运行结果的 `saveCaseRun` 有各自写入路径。
- 不能仅按 MCP 工具的 `requires_write` 判定是否改变接口：`execute_api` 在显式保存响应示例时也会保存 Target；旧版创建工具还会先创建默认实体、再保存最终实体。

## 隔离复现

已运行临时测试，调用真实的 MCP `callTool('upsert_api')`、文件存储和渲染层 store，使用临时 userData；`window.api.targets.get/list` 以直连存储的适配器替代 IPC，不访问用户业务数据。

结果：MCP 返回成功，磁盘内容和重新读取的树名称均为 `After MCP`，已打开且 `dirty=false` 的草稿仍为 `Before MCP`；关闭重开后显示 `After MCP`。要求“无须关闭重开就显示新内容”的断言失败，退出码为 1。

这证明当前 store 更新行为可以复现所述问题；完整 IPC 与真实窗口回显仍需在实现后做端到端验证。

## 用户已确认的行为

### 第一轮

1. **统一覆盖接口变更。** 覆盖 MCP 新增、修改、重命名、移动和删除接口；更新树、标签标题、请求定义、字段文档和响应示例。未打开的接口更新树；没有本地编辑的已打开接口直接更新，不切换当前标签。
2. **保护未保存草稿。** 同一接口被 MCP 更新时保留本地草稿，持续显示“接口已被 MCP 更新”，由用户选择加载最新版或继续保留草稿。
3. **提供轻量反馈。** 自动同步后在对应标签显示“MCP 已更新”；连续更新合并反馈，避免频繁弹窗。

### 第二轮

4. **保存时检查并发修改。** 保留草稿后再次保存，必须检查已保存接口是否变化。发生冲突时不能直接覆盖；用户选择加载最新版，或明确确认以本地内容覆盖。确认期间若又有新变更，重新处理冲突。
5. **删除不丢失本地内容。** MCP 删除接口时关闭无本地修改的标签；有本地编辑则保留并标记“接口已被删除”，支持复制内容或另存为新接口，不能保存回原 ID 而隐式恢复已删除接口。递归删除目录同样处理后代接口。
6. **弹窗输入也受保护。** 字段规则、接口说明等弹窗中尚未提交的输入也算本地编辑；此时暂缓替换该接口，显示有新版本。取消输入且没有其他本地修改时可应用待处理更新；提交后仍遵守保存冲突检查。

用户已逐项确认以上六项。完整实现方案待最后确认后进入实现。

## 实现方案

### 写入与通知

- 在主进程提供统一的 Target 变更通知，记录项目、目标 ID、操作来源和变更标识。通知表示已保存状态变化，客户端重新读取最终内容。
- 在成功落盘后记录变化，覆盖保存、删除、移动/重排、恢复版本、OpenAPI 导入及执行后显式保存响应示例等路径。删除包含全部实际删除的目标 ID。
- 通过 MCP 调用上下文区分来源；同一次操作对同一目标的多次写入合并通知，避免展示创建时的中间默认内容。批量操作按项目合并；部分失败时仍通知已经发生的持久化变化。
- 运行结果与接口定义变更分别处理：单纯运行不把接口标为用户未保存，也不制造定义冲突。
- 经已有 preload 白名单订阅模式传递事件；应用级订阅独立于接口页面路由，卸载时清理。
- 遵守 ADR-0001：MCP 更新被接口引用的数据模型时，通知引用接口重新解析展示内容；同一模型 ID 内容变化也必须生效，自动生成预览不能被当作用户编辑。

### 客户端应用更新

- 以当前项目和目标 ID 定位变更，只重读受影响的数据。树、标签标题和完整草稿一并更新；当前标签和发送记录保留。
- 在应用读取结果的时刻再次检查是否出现本地编辑，避免读取期间用户开始输入却被覆盖。多个异步读取按最新状态收敛，切换项目或关闭标签后丢弃过期结果。
- 本地编辑覆盖标签草稿、弹窗和表格中尚未提交的输入。存在编辑时记录待处理更新，展示持续提示；加载最新版会明确替换本地内容，保留草稿不会将其误标为已同步。
- 自己发起的保存通过操作标识确认，避免其通知被误判为 MCP 外部冲突；保存期间新增的本地输入不能被保存结果覆盖或误标为已保存。
- 初始订阅与读取避免漏事件；窗口恢复焦点时对已打开接口做状态校验，补偿休眠或加载期间错过的通知。
- 自动同步是展示更新，不产生用户编辑、额外保存或历史版本。轻量反馈与待处理冲突反馈分别呈现，不能把“已通知”当成“已同步”。

### 保存保护

- 读取接口时取得对应已保存内容的并发校验标识，保存时携带该标识；主进程在同一写入临界区内比较并保存。
- 校验标识与接口历史版本号、毫秒时间戳分别表达；历史版本签名忽略移动/排序、运行结果又不更新历史版本，不能直接作为完整并发保护。
- 确认覆盖也必须携带用户刚确认的最新标识，再次变更则再次冲突，不能设置永久跳过检查的开关。
- 已删除接口保存返回明确的已删除状态；另存为新接口生成新 ID，处理失效父目录，不复用原接口身份。

## 验收

- 真实 MCP stdio 更新一个已打开且无本地编辑的接口，在同一标签内看到新 URL、参数说明、字段规则及成功响应示例，树和标签标题同步，标签不被标为未保存。
- 覆盖当前标签、后台标签、未打开接口和切换页面的情况；更新不得抢占当前标签。
- 新增、重命名、移动、删除、递归删除目录、OpenAPI 导入、恢复版本和执行后显式保存响应的结果均能正确反映。
- MCP 修改相同 ID 的被引用模型后，接口生成的字段说明与示例展示最新内容，不把自动生成结果标为用户未保存。
- 未保存草稿或弹窗输入存在时，外部更新不丢内容，有持续提示；加载最新版和保留草稿的结果符合已确认行为。
- 旧草稿保存冲突可稳定复现；明确覆盖成功，确认期间再次更新则仍被拦截；原接口被删除后不能由旧草稿保存复活。
- 连续 MCP 更新最终显示最后一次已保存内容，不重复刷屏；异步读取、项目切换、关闭标签及保存期间继续输入均不覆盖新状态。
- 更新通知失败不让已经成功的 MCP 写入伪报失败；客户端刷新失败保留旧内容并显示可重试状态，恢复焦点后能够校验补齐。
- 运行适当的存储/MCP 与 store 回归、真实 Electron 窗口验证，以及仓库 typecheck 和 build。
