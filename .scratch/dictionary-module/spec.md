# 字典模块 Spec

Status: ready-for-agent
Date: 2026-10-25
Feature: dictionary-module

## Problem Statement

openPost 的「字典」页目前只是占位。用户无法维护字段描述、数据模型或数据库连接；接口请求体和响应示例只能手写 JSON，字段命名与描述无法复用；已有 MySQL 表结构无法转成模型；MCP agent 也读不到、改不了这些资产。用户需要像原应用一样，在一个模块里管理数据字典、数据模型与数据库连接，并让接口直接引用模型。

## Solution

在 openPost 的字典模块中提供三块完整能力：

- **数据字典**：自定义与系统内置字段描述，支持搜索、分页、类型徽标、增删改与总开关，并在模型字段与接口参数描述处联想。
- **数据模型**：模型目录树、模型列表、可视化字段编辑器、Raw JSON Schema、预览，以及复制、移动、拖拽排序与删除。
- **数据库管理**：MySQL 连接配置、测试连接、读取表结构并按表导入为数据模型；SSH 配置只记录、不执行。

同时打通两条引用链路：接口请求 Body 与响应示例可以引用数据模型，内容按模型实时生成；MCP 提供模型、字典、数据库连接的完整 CRUD 与测试/导入工具。

## User Stories

### 模块与导航

1. 作为一个 openPost 用户，我希望左栏有明确的「字典」入口，以便快速进入数据字典、数据模型与数据库管理。
2. 作为一个用户，我希望字典模块内部有「数据字典 / 数据库管理 / 全部模型 / 具体模型」页内标签，以便同时处理多个资产而不丢失上下文。
3. 作为一个用户，我希望关闭未保存的模型标签时收到确认，以便避免误丢编辑内容。
4. 作为一个用户，我希望左侧树支持搜索、分组、折叠/展开、刷新与排序，以便在大量模型和目录中快速定位。
5. 作为一个用户，我希望有一个统一的「+ 新建」菜单，包含新建数据模型、模型目录、数据字段与数据库连接，以便不用到处寻找入口。
6. 作为一个新用户，我希望没有打开标签时看到三张入口卡片，以便理解模块能做什么。
7. 作为一个用户，我希望从左侧树或模型列表打开模型时复用同一个编辑器标签，以便避免重复标签。

### 数据字典

8. 作为一个 API 设计者，我希望数据字典区分「自定义」与「系统内置」两个子标签，以便清楚哪些内容可以修改。
9. 作为一个 API 设计者，我希望每条描述展示字段名、类型徽标与描述文本，以便快速扫读。
10. 作为一个用户，我希望按参数名称或描述搜索字典条目，以便在海量字段中定位。
11. 作为一个用户，我希望字典列表分页，以便长列表仍然流畅。
12. 作为一个用户，我希望新建自定义条目时填写名称、类型、描述、备注与默认值，以便统一字段定义。
13. 作为一个用户，我希望编辑和删除自定义条目，以便字典随项目演进。
14. 作为一个用户，我希望系统内置条目只读，以便不会误改默认词汇。
15. 作为一个用户，我希望在项目级开关中启用或关闭系统内置描述，以便控制联想噪音。
16. 作为一个用户，我希望在模型字段编辑器的描述输入处获得字典联想，以便写出风格一致的字段说明。
17. 作为一个用户，我希望在接口 Header、Query、Path、Cookie 与 Body 表单参数的描述输入处获得字典联想，以便复用字段说明。
18. 作为一个用户，我希望新增同名自定义字段时有明确处理方式，以便更新而不是制造重复条目。

### 模型目录与列表

19. 作为一个 API 设计者，我希望用模型目录组织数据模型，以便按业务域分组。
20. 作为一个用户，我希望创建、重命名、删除模型目录，以便目录结构随项目演进。
21. 作为一个用户，我希望在指定目录下新建模型，以便模型落在正确位置。
22. 作为一个用户，我希望全部模型列表展示名称、别名、创建人、创建时间、最后修改人、修改时间与目录，以便审计模型资产。
23. 作为一个用户，我希望按模型名称或别名搜索，以便快速找到模型。
24. 作为一个用户，我希望按目录筛选模型，以便聚焦某个业务域。
25. 作为一个用户，我希望配置列表显示哪些列，以便聚焦当前关注的信息。
26. 作为一个用户，我希望拖拽调整模型和目录顺序，并支持移动至其他目录，以便结构符合我的认知。

28. 作为一个用户，我希望删除目录时级联删除其下模型，以便清理完整。
29. 作为一个用户，我希望删除模型前看到它被哪些接口引用，以便理解影响范围。

### 模型编辑器

33. 作为一个 API 设计者，我希望字段可以引用另一个模型，以便组合复用 schema。
34. 作为一个 API 设计者，我希望模型循环引用时得到警告而不是死循环，以便安全保存。
35. 作为一个 API 设计者，我希望用 Raw JSON Schema 编辑高级结构，以便粘贴或表达可视化编辑器未覆盖的写法。
36. 作为一个用户，我希望在 Raw 与可视化模式之间切换时校验结构，以便非法 schema 不会写坏模型。
37. 作为一个用户，我希望预览按当前 schema 生成的示例 JSON，以便快速检查结构。
38. 作为一个用户，我希望编辑模型名称、别名与描述，以便模型可读可搜。
39. 作为一个用户，我希望保存和删除模型前有明确反馈，以便避免误操作。
40. 作为一个用户，我希望字段顺序按我定义的顺序保存和展示，以便 schema 阅读自然。

### 数据库管理

44. 作为一个后端开发者，我希望保存 MySQL 连接的名称、说明、地址、端口、用户名、密码与数据库名，以便重复使用连接。

48. 作为一个用户，我希望 SSH 配置字段被保存，即使本轮不建立隧道，以便后续迭代不用重填。

### MCP

68. 作为一个 AI agent，我希望列出、读取、创建、更新、删除数据模型，以便自动化 schema 维护。

82. 作为一个开发者，我希望类型检查与构建通过，以便集成风险可控。

## Implementation Decisions

### 模块边界与导航

- 字典模块位于现有「字典」入口下，不新增全局导航项。
- 采用页内本地标签栏（数据字典、数据库管理、全部模型、具体模型），不改动现有 target 专用全局标签 store。
- 左侧树与主区共用同一套本地标签状态；标签关闭、未保存确认、`+` 新建菜单都在模块内处理。
- 无标签时展示三入口空态卡片；新建菜单统一为：数据模型、模型目录、数据字段、数据库连接。

### 存储与兼容

- 资产按项目隔离，沿用原应用的项目布局：`schemas` 区域保存模型索引与模型实体，`settings` 区域保存自定义描述与数据库连接。
- 模型索引只保存列表字段；模型实体保存完整 `data.schema` 与描述。
- 自定义字典条目单独保存；系统内置条目是代码常量，不写入项目。
- 数据库连接以数组保存，沿用原应用的 `config.default` 结构。
- 旧项目缺少文件时返回空集合，不执行迁移。
- 写入沿用现有原子写（临时文件 + rename）。

### 数据契约（来自设计阶段的类型草案）

```ts
DictionaryEntry {
  id, key, field_type: 'string'|'number'|'integer'|'boolean'|'object'|'array',
  description, remarks?, default_value?
}

DataModel {
  model_id, parent_id, model_type: 'model'|'folder',
  name, alias?, sort,
  data: { description, schema }
}

ModelSchema {
  type?, properties?, items?, required?, default?, enum?,
  description?, example?, $ref?: 'openpost://model/<model_id>',
  'x-schema-orders'?: string[], 'x-nullable'?: boolean
}

DbConnection {
  db_id, name, type: 'mysql', remarks,
  config: { default: { host, port, user, password, database } },
  ssh: { enable, host, port, username, password, auth_type, private_key, passphrase }
}
```

### 数据字典

- 系统内置条目共 19 条，字段与描述对齐原应用：`page`、`token`、`email`、`password`、`username`、`telephone`、`tel`、`mobile`、`organization`、`account`、`data`、`msg`、`result`、`success`、`error`、`authorization`、`article_id`、`date`、`price`；`page` 与 `price` 为 number，其余为 string。
- 内置描述总开关复用项目级标志 `is_describe_library`（`1` 开启、`-1` 关闭），写入项目元信息。
- 联想范围：模型字段描述 + API Header/Query/Path/Cookie/Body 表单参数描述；raw JSON 内部不做逐字段联想。
- 自定义条目按名称排序；同名条目允许存在，但 UI 提示用户确认。

### 数据模型

- 模型目录与模型共用一棵树；目录删除级联删除子节点。
- 模型名称必填，别名可选；创建人与修改人记录本地用户名。
- `ModelSchema` 是唯一事实来源；可视化编辑器读写 schema，并用 `x-schema-orders` 保持字段顺序、用 `x-nullable` 表示可空。
- 模型引用使用稳定协议 `openpost://model/<model_id>`；生成与校验都必须识别该协议。
- 删除被引用的模型：先返回引用列表并警告，确认后删除；接口上的引用保留为失效引用，不自动改写接口。
- 模型重复名称在保存时提示，但允许用户改名后继续。

### 模型引用与生成（见 ADR-0001）

- 请求体新增 `body.model_id`；响应示例新增 `expect.model_id`。
- `raw` 只保存最近一次生成结果用于预览与兼容；发送/展示时重新生成。
- 生成优先级：`example` → `default` → `enum[0]` → 类型占位；对象按 `x-schema-orders` 顺序生成；数组生成一个元素。
- `$ref` 递归解析，深度上限 8，使用 seen 集合检测循环；循环或失效引用返回 warning，不阻断保存。
- 请求体在引用状态下只读；点「编辑」必须确认并解除引用，保留当前 JSON。
- 响应示例关联模型后实时生成只读内容；模型失效时显示红色徽标与解除入口。

### 数据库管理（见 ADR-0002）

- 仅支持 MySQL，使用 `mysql2` 直连；其他数据库类型不在本轮。
- 密码等凭据明文保存在项目设置中；不引入平台密钥加密。
- 仅实现「默认配置」，不实现按项目环境覆盖。
- SSH 配置完整保存，但测试连接与导入只走直连；SSH 启用时明确返回/展示「隧道后续支持」，不静默降级。
- 测试连接执行 `SELECT VERSION()`，超时 8 秒；失败返回可读错误。
- 表清单与列信息通过 `information_schema` 读取；导入前勾选表并选择目标目录。
- 导入策略：更新同名模型、跳过同名模型、创建副本；可对全部表统一应用。
- 每表生成一个模型：表名 → 模型名，表注释 → 模型描述，列注释 → 字段描述，可空性 → `required`，默认值 → `default`。
- 类型映射：`tinyint(1)` → boolean；整数类型 → integer；decimal/float/double → number；日期、字符串、enum/set → string；json → object；binary/blob → string。`bigint` 映射为 integer 并提示精度风险。
- 删除数据库连接不删除已导入模型。

### 主进程、IPC 与 MCP

- 扩展存储模块：字典 CRUD 与项目开关、模型 CRUD/复制/移动/排序、引用扫描、示例生成、数据库连接 CRUD/测试/表清单/导入。
- 新增 IPC 通道：`dictionary:*`、`model:*`、`db:*`；preload 暴露 `dictionary`、`models`、`db` 命名空间。
- 示例生成与引用解析放在主进程，UI 与 MCP 共用同一实现，避免行为分叉。
- MCP 新增工具：
  - `list_data_models` / `get_data_model` / `create_data_model` / `update_data_model` / `delete_data_model`
  - `list_dictionary_entries` / `create_dictionary_entry` / `update_dictionary_entry` / `delete_dictionary_entry`
  - `list_db_connections` / `create_db_connection` / `update_db_connection` / `delete_db_connection`
  - `test_db_connection` / `import_db_schema`
- 权限：CRUD 写操作要求 `allow_write`；测试连接与导入要求 `allow_execute`；读取工具不受写权限限制。
- MCP 返回数据库连接时脱敏密码、私钥与 passphrase；删除类工具要求 `confirm: true`，模型删除返回引用列表。
- MCP 工具名不带 `apipost_` / `openpost_` 前缀，与现有 30 个工具一致。

### UI 细节

- 数据字典页：自定义/系统内置子标签、搜索、分页（10 条/页）、类型徽标、内置描述开关；自定义行提供编辑/删除。
- 数据库管理页：名称/数据库类型/说明/操作四列；新建按钮；连接弹窗包含名称、说明、类型、常规/SSH 标签、测试连接、取消/确定；不显示「默认环境」。
- 全部模型页：搜索、筛选、列设置；列包含名称、别名、创建人、创建时间、最后修改人、修改时间、目录；空态插画。
- 模型编辑器：名称/描述、Raw 编辑/预览/生成代码（禁用）/智能导入（禁用）、可视化字段树；字段支持类型、必填、可空、默认值、枚举、描述、引用模型；Mock 列占位。
- 模型编辑器关闭未保存标签时确认；Raw 与可视化切换需通过 schema 校验。
- 响应示例与请求 Body 各提供「引用模型」入口；引用状态显示模型徽标与解除按钮。

### 安全、错误与边界

- 凭据只保存在本地项目数据中；导出、分享与 MCP 输出必须脱敏。
- 数据库错误、SSH 未实现、同名导入、循环引用、失效引用、非法 schema 都要给出可读提示，不静默失败。
- 数据库表清单为空、连接超时、认证失败、目标目录不存在等边界均返回明确错误。
- 模型/目录删除前提示影响范围；目录删除级联，模型删除保留 API 引用。
- 列表与预览对超深 schema 做深度保护，避免无限递归。

## Testing Decisions

### 什么算好测试

- 只测试外部可观察行为：通过存储 API、IPC、MCP 工具与 UI 操作验证结果，不断言内部文件布局或实现细节。
- 使用真实 MySQL 做集成验证，不用 mock；断言用户可见的模型结构、字段映射与错误消息。
- 每个测试用独立项目与唯一模型/连接名，避免相互污染；测试结束清理临时数据库与临时项目数据。
- 负向用例与正向用例同等重要：循环引用、失效引用、同名导入、认证失败、权限拒绝、非法 schema。

### 测试缝

1. **现有 Electron smoke 脚本（首选、现有缝）**：扩展主进程级 smoke，覆盖字典 CRUD、项目开关、模型 CRUD/复制/移动/排序、引用扫描、示例生成（含循环/失效）、数据库连接 CRUD/测试/导入、MCP 全部新工具与权限拒绝。沿用脚本现有的真实服务、显式汇总与退出码风格。
2. **UI 自动化（新增缝）**：通过 Electron 调试 CDP 驱动已构建应用，覆盖模块导航、字典子标签/分页/联想、模型列表/编辑器双模式/预览、引用弹窗与解除、数据库连接弹窗与导入流程。新增 Playwright/CDP 依赖；这是本轮唯一新增的测试缝。
3. **MySQL 集成**：使用本机 MySQL 8.4.9 创建 `openpost_dict_test` 临时库，建表覆盖整数、字符串、decimal、datetime、tinyint(1)、json、注释、可空与默认值；验证连接、表清单与导入映射；结束后删除临时库。

### 被测试的模块

- 数据字典：内置 19 条、自定义 CRUD、项目级开关、联想数据源。
- 数据模型：目录/模型 CRUD、复制/移动/排序、名称冲突、级联删除。
- Schema 生成与引用：example/default/enum/类型占位优先级、嵌套对象/数组、`$ref`、循环与失效引用。
- API 引用：引用扫描、删除警告、失效引用标记、请求体/响应示例的生成结果。
- 数据库：连接配置 CRUD、直连测试、SSH 启用提示、`information_schema` 表/列读取、类型映射、同名导入策略。
- MCP：工具参数校验、写/执行权限、凭据脱敏、删除确认与引用列表。
- UI：页内标签、左树、字典分页/开关、模型编辑器、引用选择器、数据库导入向导。

### 先例

- `scripts/smoke.ts` 已有的 HTTP → 流程 → MCP → OpenAPI 端到端 smoke 是本轮后端测试的直接先例。
- 调试 CDP 开关已经存在，可作为 UI 自动化的连接点；仓库当前没有 Playwright 测试，需要新增一套最小配置。
- 仓库没有单元测试框架；本轮不新增 Vitest/Jest，避免第二个单元测试缝。

### 明确不测

- 不测内部 JSON 文件的字段顺序或原子写实现细节。
- 不 mock MySQL；数据库相关断言必须走真实实例。
- 不对生成的示例 JSON 做全量快照；只断言关键字段、类型与 warning。

## Out of Scope

- MySQL 之外的数据库类型（PostgreSQL、SQL Server、Oracle、Redis、MongoDB、ClickHouse、达梦等）。
- SSH 隧道真实建立与私钥认证执行；本轮只保存配置并提示后续支持。
- 按项目环境覆盖数据库连接参数。
- JSON Schema 文件导入/导出、模型代码生成、智能导入（JSON 示例转 schema）。
- Mock 规则、Mock 服务联动与字段级 Mock 配置。
- OpenAPI 双向同步、模型版本历史、跨项目模型共享。
- 字典导入/导出与「保存临时数据」。
- 将字典模块并入全局 target 标签栏。
- 多用户同步、权限体系与团队协作。
- 数据库查询执行器与写回数据库。
