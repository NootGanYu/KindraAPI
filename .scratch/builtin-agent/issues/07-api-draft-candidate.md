## Answer

新增协议无关 `propose_api_change` 计划步骤。批准计划只创建不可变 P 候选；用户在既有接口版本入口查看双栏差异并应用，主进程才更新本机草稿。正式定义与 v 版本均保持不变。候选快照和审阅状态分别存储，超 100 条不裁剪；脱敏占位符被拒绝，普通字段修改保留本地真实认证值。

`src/main/agent/drafts.ts` 管理项目/接口草稿、候选、基线检查和退出快照；`src/shared/agentDraft.ts` 是后续合并/保存票的接口。应用时同时比较草稿定义与正式 revision，变化则标记冲突并暂停，不覆盖。Renderer 同步手工编辑；关闭标签、切项目或重启后由主进程草稿恢复。

真实退出先提示并停止任务，随后通过 `saveManualDraftOnQuit` 在主进程同一同步操作内检查 Agent 所有权和 revision，确保自动保存不会将 Agent 草稿落为定义；纯手工草稿仍自动保存。退出快照按定义去重。原生退出兜底再次停止并暂存，不重放任务。

Diff 使用有规模上限的 LCS 对齐行序列，重复行增删不会隐藏；大文本采用保守整块差异。

验证通过：`npm run typecheck`、`build`、`test:agent-drafts`（真实存储/模型回环、无隐式保存、双基线冲突、不可变候选、102 条待确认保留、敏感值、Git 边界、退出去重及自动保存拒绝）；`test:agent-draft-ui`（真实 Electron 修改计划批准、原版本入口、重复行删除差异、草稿应用、后续人工编辑、原生退出先取消再确认、重启恢复及纯人工自动保存）；`test:client-sync`、`test:documentation`、`test:agent-plan-protocols`（双协议只读/依赖/权限回归）。

已合入 06 的双协议适配，未扩展 08 三方自动合并或 09 正式保存。
