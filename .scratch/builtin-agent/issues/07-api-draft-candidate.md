# 07: 首次接口草稿修改与候选

**What to build:** 已授权计划修改一个接口草稿，同时在版本入口显示待确认候选。

**Blocked by:** [05 只读连续操作与依赖](05-read-only-steps.md)

**Status:** claimed

父规格：[内置 Agent 规格](../spec.md)。22 张票共同构成已确认首版；新增工具复用两协议的协议无关工具契约。

验证约定：使用 Renderer 实际调用的应用命令/事件、隔离 userData、真实存储及业务能力；按需使用回环模型和目标 HTTP，关键用户旅程覆盖 Electron UI。

- [ ] 提案与草稿分离；应用后只修改草稿，正式定义不变，版本入口显著提示候选并支持普通双栏 Diff。
- [ ] 一个逻辑修改创建本机不可变 P 编号候选，未解决候选不裁剪，不进入 Git、不占正式版本号；Agent 没有 save 步骤不能持久化定义。
- [ ] 应用前草稿或正式定义已变化时暂停该对象，绝不覆盖；08 才提供自动合并。
- [ ] 退出时保护 Agent 草稿不走 dirty 自动正式保存，提示运行任务并暂存，重启可恢复；纯手工草稿保持原行为。
- [ ] 真实存储、命令及 Electron UI 验证草稿、候选、退出重启及 MCP 回归。
- [ ] 在引入本票能力前完成窄路径兼容重构，并验证外部 MCP 权限和行为回归。
