# 内置 Agent 集成

Status: ready-for-agent

## Problem Statement

用户需要在 Kindra 项目内连续理解、修改和测试接口、接口用例与跨接口执行流程。目前用户必须手工衔接上下文、编辑、请求和结果分析；外部 MCP 工具也不能直接提供内置会话、草稿审阅与计划授权体验。用户需要在控制敏感信息、执行范围及未保存修改的同时，审阅和恢复 Agent 的工作。

## Solution

提供项目内置的连续操作 Agent。用户配置模型连接，在本项目发起会话并批准具体计划；Agent 在授权范围内读取脱敏上下文、处理草稿、执行测试和分析结果。修改有候选版本与冲突审阅，正式保存是计划中的独立步骤。会话和 Agent 工作记录保存在本机，支持恢复、检查和本地撤销。

这是待实施规格；本地存储、执行器和现有 MCP 能力可复用，但不能假定现有实现已经满足 Agent 的权限、草稿或快照要求。

## User Stories

1. 作为项目使用者，我希望打开内置 Agent，以便在工作区内完成连续任务。
2. 作为项目使用者，我希望 Agent 理解 HTTP 接口，以便解释和修改接口。
3. 作为项目使用者，我希望 Agent 处理单接口 API Case，以便维护参数覆盖与断言。
4. 作为项目使用者，我希望 Agent 分析请求和用例执行结果，以便定位问题。
5. 作为项目使用者，我希望 Agent 操作跨接口 Execution Flow，以便完成多步骤测试。
6. 作为项目使用者，我希望自然语言任务可以连续执行多个步骤，以便减少手工切换。
7. 作为项目使用者，我希望默认只读取当前项目的必要上下文，以便限制数据范围。
8. 作为项目使用者，我希望发送前脱敏敏感内容，以便减少凭据泄露。
9. 作为项目使用者，我希望明确本轮读取的项目及必要上下文范围，以便了解数据使用范围。
10. 作为项目使用者，我希望工具结果也经过脱敏，以便敏感信息不会经工具返回泄露。
11. 作为项目使用者，我希望接口文档和响应只作为数据处理，以便其中的文字不能擅自授权操作。
12. 作为项目使用者，我希望 Agent 会话按项目区分，以便对话与工作对象保持一致。
13. 作为项目使用者，我希望重启后继续本机会话，以便接续先前工作。
14. 作为项目使用者，我希望手动删除 Agent 会话和记录，以便控制本地历史。
15. 作为项目使用者，我希望 Agent 对话、计划、工具结果和报告不进入 Git，以便本地工作不会意外进入项目版本库。
16. 作为项目使用者，我希望原有手动 Flow 报告保持原状，以便既有工作流不被迁移改变。
17. 作为项目使用者，我希望配置多个模型连接，以便按项目选择服务。
18. 作为项目使用者，我希望填写 API 地址、Key、模型名和协议，以便连接所选服务。
19. 作为项目使用者，我希望设置项目默认连接，以便减少重复选择。
20. 作为项目使用者，我希望使用 Chat Completions 或 Responses，以便连接支持相应协议的服务。
21. 作为项目使用者，我希望检测连接和工具调用能力，以便知道模型能否执行连续操作。
22. 作为项目使用者，我希望仅支持文本的模型仍可聊天并说明连续工具操作不可用，以便理解能力限制。
23. 作为项目使用者，我希望 Key 安全保存在本机且不会出现在普通配置读取、日志和项目文件中，以便保护凭据。
24. 作为项目使用者，我希望每轮任务固定模型配置，以便后续修改或删除连接不会改变正在运行的任务。
25. 作为项目使用者，我希望服务不会在任务中自动切换，以便了解数据发送目标。
26. 作为项目使用者，我希望先看到 Agent Plan 的目标、对象、环境、步骤、依赖与影响，以便决定是否授权。
27. 作为项目使用者，我希望按本轮计划批准具体范围，以便授权后的连续操作无需逐步重复确认。
28. 作为项目使用者，我希望范围扩大或冲突时重新确认，以便保持授权有效。
29. 作为项目使用者，我希望执行端逐步检查权限，以便模型或界面不能绕过批准范围。
30. 作为项目使用者，我希望执行计划明确包括既有脚本、变量更新和额外请求，以便理解实际副作用。
31. 作为项目使用者，我希望已配置文件上传纳入执行计划，以便了解文件传输范围。
32. 作为项目使用者，我希望新增或修改脚本、目标或文件范围时重新核对授权，以便控制新的副作用。
33. 作为项目使用者，我希望会写入响应示例的执行同时检查写入权限，以便执行授权不会隐含额外保存。
34. 作为项目使用者，我希望 Agent 默认修改草稿，以便正式定义不会因生成自动改变。
35. 作为项目使用者，我希望使用草稿测试，以便在保存前验证修改。
36. 作为项目使用者，我希望保存定义是单独的计划步骤，以便明确控制持久化。
37. 作为项目使用者，我希望已批准计划中的保存步骤校验通过后直接执行，以便不重复授权。
38. 作为项目使用者，我希望没有批准保存时正式定义保持不变，以便安全审阅草稿。
39. 作为项目使用者，我希望 Agent 提案在采纳前独立于草稿和正式定义，以便决定是否应用。
40. 作为项目使用者，我希望不同字段的并发修改自动合并，以便保留双方无冲突的工作。
41. 作为项目使用者，我希望相同字段的冲突展示并由我选择结果，以便避免静默覆盖。
42. 作为项目使用者，我希望未解决冲突不能正式保存，以便避免保存不确定结果。
43. 作为项目使用者，我希望保存时检查已保存定义的并发变化，以便不覆盖其他更新。
44. 作为项目使用者，我希望未知业务规则要求澄清，以便不会把推测写成接口契约。
45. 作为项目使用者，我希望每个接口的版本入口显示 Agent 修改和冲突，以便集中审阅。
46. 作为项目使用者，我希望明显看到待确认版本，以便不会遗漏 Agent 工作。
47. 作为项目使用者，我希望区分已保存版本、待确认候选和冲突候选，以便理解各自状态。
48. 作为项目使用者，我希望普通修改以 Git Diff 风格查看，以便快速识别差异。
49. 作为项目使用者，我希望冲突显示基线、当前内容、Agent 内容及合并结果，以便作出选择。
50. 作为项目使用者，我希望恢复候选到草稿与正式保存分开，以便恢复不会隐式持久化定义。
51. 作为项目使用者，我希望不采纳候选仍保留审阅历史，以便追溯决定。
52. 作为项目使用者，我希望撤销已应用候选时检查后续编辑冲突，以便不覆盖人工修改。
53. 作为项目使用者，我希望已保存版本关联对应候选，以便追踪修改来源。
54. 作为项目使用者，我希望其他未解决候选不因一次保存而消失，以便分别处理提案。
55. 作为项目使用者，我希望用例和 Flow 也可审阅版本和撤销，以便跨对象修改得到同等保护。
56. 作为项目使用者，我希望删除或尚未正式创建对象的候选仍可在项目汇总找到，以便恢复和审阅。
57. 作为项目使用者，我希望整轮本地修改支持冲突检查后撤销，以便安全回退 Agent 工作。
58. 作为项目使用者，我希望知道本地撤销不能回滚远端请求，以便理解外部影响。
59. 作为项目使用者，我希望执行绑定项目、环境和定义快照，以便工作区变化不改变运行目标。
60. 作为项目使用者，我希望运行变量可演进且写回检查冲突，以便正常登录和后续步骤仍能工作。
61. 作为项目使用者，我希望环境删除或授权变化时暂停，以便不在错误范围执行。
62. 作为项目使用者，我希望失败对象及依赖暂停、独立步骤继续，以便保留部分成功。
63. 作为项目使用者，我希望远端结果未知时不自动重发，以便避免重复产生外部副作用。
64. 作为项目使用者，我希望切换项目后原任务仍绑定原项目和环境，以便后台任务不串项目。
65. 作为项目使用者，我希望退出前获知运行任务、退出时仅暂存 Agent 草稿并在重启后恢复，以便既不隐式保存定义也不自动重放请求。

## Implementation Decisions

**产品契约：**

- 按上述范围交付 Agent 会话、计划、执行、草稿和版本审阅；首版不提供字典、MQTT、数据库、shell 或任意文件读写的 Agent 工具，批准计划不会自动扩展业务范围。
- 本轮计划明确主体、对象、项目、环境、修改、执行步骤、依赖与副作用；服务端逐步复核参数产生的实际权限，范围改变或冲突时暂停并重新确认。接口响应及文档内容不能授予权限。认证头、Cookie、密钥和环境变量值默认留在本机，真实值仅供本地实际请求按需使用；模型输入及返回模型的工具结果均脱敏，运行日志及普通配置读取不得泄露 Key。
- 计划中的保存是独立步骤；已批准并通过校验后自动保存，关联最终正式版本及对应候选链，不重复授权或清除其他提案。未批准保存时正式定义不变。
- 保留字段文档硬性校验：新接口必须满足既有完整规则，增量更新校验本次提交字段；缺乏业务依据时澄清，不从示例推断规则。模型引用保持实时生成语义：正式定义继续保存 model_id 引用，后续新运行读取当时模型，不将展开快照永久写入定义；执行快照只固定本轮解析的定义依赖，运行变量可演进。
- 项目和实体草稿独立于页面生命周期；执行固定项目、获批环境、草稿及定义依赖快照。获准变量差量写回须检查冲突；环境删除或授权变化暂停。
- 按计划依赖保留部分成功，失败对象及依赖暂停，已证明独立步骤可继续；未知依赖保守阻塞，可串行执行。远端结果未知须单独记录且禁止自动重发；重试仅限未完成步骤，不承诺整批原子回滚。
- 每轮固定模型连接配置；支持多个本机连接、项目默认及两种明确选择的 OpenAI 兼容协议。之后编辑或删除连接不改变运行中任务，也不自动切换服务。检查工具能力，仅文本模型可用于文本聊天，但连续工具操作不可用；密钥由主进程保护且不从普通读取接口返回。
- Agent 会话、计划、工具结果、执行报告和候选本地保存、不进 Git，保留至手动删除；手动 Flow 报告不迁移。本功能不自动 Git 提交或推送。
- 切换项目不更改任务绑定；真实退出前提醒、停止模型流及工具，并仅暂存 Agent 草稿。重启提示恢复，不自动正式保存或重放网络请求；隐藏到托盘不等同退出。纯手工草稿退出沿用现有行为；现有 dirty 标签退出自动保存路径不能绕过 Agent 草稿的保存授权。
- 整轮本地撤销覆盖接口、API Case 和 Flow 的可编辑变更，检查后续修改冲突并展示差异；保留身份和运行记录，不声称撤销远端副作用。

- 无冲突字段自动合并，仅冲突字段需要确认；普通 Diff 默认双栏，可额外提供统一视图。

**模块与接口职责（建议）：**

- 主进程模型适配与凭据管理负责协议、能力检测和安全配置。
- 任务与计划授权服务负责范围校验、依赖、生命周期和执行结果。
- 共享业务工具与执行上下文负责复用既有能力并隔离内置 Agent 与 MCP 策略。
- 跨项目实体草稿与候选审阅服务负责快照、合并、版本、恢复和撤销。
- Renderer 通过应用命令与事件边界呈现计划、进度、冲突和恢复。
- Flow 现有实时读取须建立本轮快照边界，入口与节点使用同一获批环境。

**技术建议默认，实施时验证：**

- 通过共享业务工具注册与独立执行上下文复用现有能力；内置 Agent 不依赖伪造外部 MCP 启用状态，外部 MCP 原权限语义保持不变。
- 三方比较基线、当前草稿与提案，按稳定实体 ID 合并无冲突字段，仅冲突字段请求确认；raw body 和脚本字符串整体比较，数组排序细节需验证。正式 revision 与草稿快照或编辑版本分别检查。
- 每个逻辑修改步骤创建不可变候选；退出只补录未快照内容并去重，不按 token 或按键创建。候选独立本机集合、`P` 编号，与正式 `v` 版本在入口合并查询，未解决候选不受既有 100 条裁剪。
- 同入口区分正式版本、待确认候选和冲突候选，普通差异默认使用双栏，可额外提供统一视图，冲突显示 base/current/agent 与合并结果。候选快照需独立 diff；现有 Git 文件 diff 不能直接读取候选。
- 不采纳仅改变审阅状态并保留历史；已应用变更的撤销另行检查冲突。已删除或尚未正式创建对象通过项目级汇总及墓碑保留审阅和撤销证据。
- 统一版本签名与 revision 的可编辑定义口径，同时保留各自标识；现有恢复不覆盖用例及自定义属性，不能直接作为完整撤销。Flow 需同等版本入口。

## Testing Decisions

测试从用户可观察结果验证契约，不断言内部实现细节、逐个函数 mock 或内部调用次数。已确认主要集成边界采用 Renderer 实际调用的主进程应用命令和事件：启动任务、批准计划、处理冲突、取消、切项目及恢复；沿用现有 IPC/preload 接口结构，使用隔离的 userData、真实存储、业务工具和执行器。

外部模型使用回环服务分别模拟 Chat Completions 与 Responses，目标请求使用可控回环 HTTP 服务；其余业务路径尽量真实。通过真实时序制造远端结果未知，并断言目标服务接收请求后断开连接时计数不因自动重发增加，已成功步骤也不被重发。

覆盖矩阵至少包括：

- 外部 MCP 原有权限、工具、同步与文档门槛回归；未知业务字段不可猜测，模型引用实时生成与执行快照的边界。
- 无 save 不改变正式定义；批准含 save 的计划校验通过后无需二次确认，关联候选且不清除其他提案。
- 草稿三方合并、稳定 ID、同字段冲突、正式 revision 变化和保存阻断；用例与 Flow 的完整恢复及后续人工修改冲突。
- 候选编号、不可变逻辑步骤、退出去重、未解决候选不裁剪、不采纳保留、删除墓碑、未创建对象汇总与整轮撤销。
- 两种模型协议及工具能力检测、仅文本聊天而禁用连续工具操作、绑定配置、凭据和上下文脱敏、响应中的指令不构成授权。
- 会话和全部 Agent 记录重启后可读、手动可删除，且这些本地记录不出现在项目 Git 工作区；已获批保存的正式定义仍遵循现有项目 Git 管理。运行日志和普通配置读取无 Key 泄露。
- 纯手工草稿退出沿用现有行为，Agent 草稿退出仅暂存，dirty 自动保存路径不能绕过授权。
- 计划范围、脚本与文件副作用、参数引入写权限、Flow 定义依赖快照、环境绑定、变量演进及写回冲突。
- 部分成功、依赖暂停、独立步骤继续、结果未知不自动重试、取消、切项目、退出提示及重启不重放。

少量 Electron UI 关键旅程覆盖计划授权、Git Diff 风格冲突和待确认提醒、切项目、退出与重启恢复。现有客户端同步、文档校验、调试运行时及 Electron UI smoke 测试提供真实存储、回环请求、取消及隔离 userData 的先例。

## Out of Scope

首版不提供新增字典、MQTT、数据库、shell 或任意文件系统读写 Agent 工具；整批原子回滚或远端副作用撤销；任意 API 协议兼容保证；自动提交或推送 Git；迁移既有手动 Flow 报告。此规格不把 Apipost 访客页面的静态线索当作其服务端实现事实。
