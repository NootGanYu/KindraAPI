# AI 执行计划：受控运行与暂停续跑

Date: 2026-11-03  
Feature: ai-execution-plan

Status: resolved

完成日期：2026-11-03。13 张工单与最终审查修复均已完成；验证记录见 [工单导航与验收](issues/README.md)。

## Problem Statement

用户需要让外部 MCP 客户端与人工共同编排、执行和排查跨接口流程。现有 Execution Flow 运行时读取可变接口，环境选择可能不一致；执行过程中无法在步骤边界暂停、修改接口后安全继续，也无法清楚追溯同一次 Run 中使用的定义版本。用户不应为了修改尚未执行的接口而重放已经产生远端影响的请求。

## Solution

用户和外部 MCP 客户端共同使用可保存、可重复运行的 Execution Flow。每次 Run 从已保存定义构建 Execution Snapshot，并固定运行环境；用户请求暂停后，当前完整逻辑步骤结束，界面展示暂停状态。用户修改并保存接口，预览剩余步骤受影响的实际请求，解决冲突后手动继续。已完成结果和运行变量保留，报告标识版本切换。外部 MCP 可编排并查看运行，但不能解除用户手动暂停。该功能不等待内置 Agent。

## User Stories

1. 作为用户，我希望保存 Execution Flow，以便重复运行跨接口流程。
2. 作为用户，我希望引用已保存 API，以便复用项目定义。
3. 作为用户，我希望选择环境和 Server，以便请求发往预期服务。
4. 作为用户，我希望运行开始时固定定义，以便知道本轮依据。
5. 作为用户，我希望运行不改变已保存 API，以便原定义保持可维护。
6. 作为用户，我希望模型引用在启动时解析，以便遵循实时生成规则。
7. 作为用户，我希望继承配置也纳入运行快照，以便运行内容可追溯。
8. 作为用户，我希望脚本与步骤定义固定，以便运行途中编辑不会悄悄改变行为。
9. 作为用户，我希望初始变量进入本轮上下文，以便后续步骤一致使用。
10. 作为用户，我希望步骤提取 token，以便后续请求使用登录结果。
11. 作为用户，我希望提取对象 ID，以便后续步骤引用已创建对象。
12. 作为用户，我希望运行中修改全局变量默认不影响本轮，以便避免隐式变化。
13. 作为用户，我希望看到运行和编辑版本，以便分辨修改何时生效。
14. 作为用户，我希望请求暂停，以便调整尚未执行的接口。
15. 作为用户，我希望看到正在暂停，以便知道当前步骤尚未结束。
16. 作为用户，我希望完整逻辑步骤结束后暂停，以便前置、请求、后置和断言使用一致版本。
17. 作为用户，我希望暂停期间编辑并保存 API，以便后续步骤采用新定义。
18. 作为用户，我希望看到所有受影响的剩余引用，以便核对修改范围。
19. 作为用户，我希望同一 API 的多次剩余引用都能更新，以便避免遗漏。
20. 作为用户，我希望看到实际生效请求，以便发现步骤覆盖隐藏了已保存修改。
21. 作为用户，我希望解决覆盖冲突后手动继续，以便控制后续远端操作。
22. 作为用户，我希望保存失败时保持暂停，以便不会运行旧数据。
23. 作为用户，我希望接口删除或并发变更时阻止继续，以便先处理冲突。
24. 作为用户，我希望已完成步骤不重跑，以便避免重复远端写入。
25. 作为用户，我希望暂停后保留运行变量，以便继续依赖已完成步骤。
26. 作为用户，我希望变更扩大授权范围时重新确认，以便控制执行范围。
27. 作为用户，我希望依赖失败步骤的后续步骤暂停，以便不使用无效结果。
28. 作为用户，我希望可证明独立的步骤继续，以便保留有效工作。
29. 作为用户，我希望无法证明独立时保守阻塞，以便避免错误调用。
30. 作为用户，我希望失败或结果未知不自动重试，以便避免重复操作。
31. 作为用户，我希望查看逐步进度及最终报告，以便定位问题。
32. 作为用户，我希望报告记录版本切换点，以便解释不同步骤的请求依据。
33. 作为用户，我希望取消不假装撤销已发请求，以便理解远端状态。
34. 作为用户，我希望循环内暂停后从正确位置继续，以便不重复已执行迭代。
35. 作为用户，我希望重复点击继续不会产生重复请求，以便安全操作。
36. 作为外部 MCP 客户端，我希望创建和更新流程，以便编排测试。
37. 作为外部 MCP 客户端，我希望异步启动并查询 Run，以便不长期占用工具连接。
38. 作为外部 MCP 客户端，我希望读取进度和报告，以便分析结果。
39. 作为用户，我希望 MCP 不能自动解除我的暂停，以便保留人工控制。
40. 作为现有 MCP 客户端，我希望原同步执行正常完成时仍返回摘要，以便兼容现有调用。
41. 作为管理员，我希望 MCP 权限收紧后禁止未授权操作，以便保护项目。
42. 作为用户，我希望既有条件、循环及脚本仍可运行，以便升级不破坏已有流程。

## Implementation Decisions

- 已确认产品交互遵循 ADR-0008；其他实现细节是本规格的开工默认，并非逐项用户确认。Flow 保存 API 引用；Run 启动时从已保存 API、继承配置及模型解析运行快照，不将解析结果写回持久化 API，遵循 ADR-0001。未保存 API Draft 不作为本期依赖。
- 将 Project、Environment、Server 地址、Flow 和 API 定义、继承、模型及脚本绑定到 Run。运行变量与定义快照分开：初始变量复制进入上下文，步骤输出可更新本轮变量。文件等外部依赖记录摘要并在使用前核对，变化时暂停审查；固定定义不保证远端结果一致。
- UI 和 MCP 共用运行管理服务，独立执行各自身份及权限策略，不伪造 MCP 配置供其他调用方使用。继续操作必须来自用户界面；MCP 可请求暂停并查询，但不能解除用户手动暂停。
- 状态至少区分运行、正在暂停、已暂停、审阅变更、完成、取消、失败及远端结果未知。暂停在完整逻辑步骤边界生效；逻辑步骤包括前置脚本、请求、后置脚本和断言。稳定步骤标识及逻辑分组须贯穿 MCP 步骤转换、运行、报告和循环；恢复保存游标、嵌套调用栈及变量，不能从头重启。
- 保存成功后为所有受影响的剩余引用构建新快照，已完成步骤和结果保持原版本；展示切换点、版本与有效请求。对步骤 input 覆盖与新定义的冲突必须显式检查和呈现，不能仅刷新目标引用；保存失败、删除或 revision 并发变化阻止恢复，恢复前再次校验。范围扩大时重新确认授权。
- 已有八类事件、条件、循环和存量脚本语义保持兼容；MCP 旧 steps 格式继续可用，不能在转换或更新时静默丢失已有条件、循环。原版清除接口脚本的行为不作为本期兼容要求。
- 运行控制以兼容增量提供 `start_flow_run`（返回 run_id 和状态）、`get_flow_run`（返回状态、进度及报告引用）和 `pause_flow_run`（请求步骤边界暂停）；名称为本规格建议的稳定合同。用户在 UI 审阅后手动继续，不暴露可解除手动暂停的 MCP 继续工具。无暂停的外部 MCP 流程正常运行，保存接口本身不等于继续。旧 execute_flow 正常无暂停时保留最终摘要语义；出现暂停或超时时返回可查询的明确状态和 run_id，不重放或无限占用连接。重复继续幂等，权限在操作时重新校验。
- 失败依赖的步骤暂停；只有可证明独立的步骤可以继续，无法证明时保守阻塞。失败、取消和远端结果未知分别表达，不自动重试；恢复前验证已完成输出满足剩余步骤前置条件。

### MCP 增量合同

以下名称及参数为可编码的技术默认；所有操作绑定指定项目，权限在每次操作时校验。

| 工具 | 输入 | 行为 |
| --- | --- | --- |
| `start_flow_run` | `project_id`、`flow_id`、`environment_id`、`request_id` | 异步启动，立即返回 `run_id` 和真实状态。同项目同 `request_id` 且输入相同返回同一 Run；输入不同拒绝，不再次执行。 |
| `get_flow_run` | `project_id`、`run_id` | 返回状态、进度、已完成部分结果及可用报告引用。 |
| `pause_flow_run` | `project_id`、`run_id` | 请求在逻辑步骤边界暂停，返回真实状态；重复请求不得启动新 Run。 |
| `cancel_flow_run` | `project_id`、`run_id` | 有界取消并返回当前状态；不保证已发出的远端操作回滚。 |

不提供 MCP 工具解除用户手动暂停。无暂停的外部 MCP 编排正常执行；保存接口不等于继续。旧 `execute_flow` 保持兼容：最多等待 20 秒，正常完成返回原有最终摘要；暂停或到达等待上限则返回 `run_id` 与真实状态，后续查询或由用户继续。桥接层现有约 30 秒超时不应被占满；断开连接不重启或重放 Run。

### 生命周期及持久化

- 同一 Project / Flow 同时最多一个活动 Run，暂停中的 Run 也占用此位置。活动 Run 绑定固定 Flow 结构，期间禁止删除该 Flow；切换项目后后台运行仍绑定原项目，可返回查看。
- 启动使用当前已保存 API；普通保存不改变正在运行的快照。存在需要使用的未保存草稿时由用户主动保存，运行按钮不得隐式保存草稿。模型引用解析仅进入运行上下文；持久引用不变，普通编辑与单接口发送仍按 ADR-0001 实时解析。
- 退出时提示终止活动运行；重启展示中断状态和已保存的部分结果，不自动续跑。不能确认远端结果时标记结果未知，不伪装成普通失败或自动重试。进度及部分结果逐步持久化。
- 新增运行日志及快照证据本地保存且不进入 Git；既有报告保持可读，不批量迁移。展示和持久证据对敏感值脱敏，避免在报告或日志泄漏凭据。
- 延续 Kindra 脚本顺序：步骤前脚本 → 接口前脚本 → 请求 → 接口后脚本 → 步骤后脚本及断言。同一逻辑步骤内不切换版本。循环执行实例按稳定 event ID 与 iteration 标识，已执行迭代保留，未来迭代可采用经审阅的新快照。

### 冲突、依赖与权限

- 步骤覆盖中未冲突的值保留。新 API 修改了被步骤覆盖的字段时列为冲突，body 整体覆盖也须提示；用户逐项选择新 API 值或保留步骤覆盖。字段删除或类型不兼容必须解决后才可继续。预览展示实际生效请求，选择只写入本 Run revision，不隐式修改持久 Flow input；主动编辑 Flow 是独立操作。
- 请求错误、任一接口脚本或步骤脚本错误、显式断言失败均使步骤失败；HTTP 状态不单独套用原版非 200 失败规则，按现有显式断言判断，201 可以通过。依赖默认保守串行，只有显式依赖声明才能证明独立，不扫描脚本猜依赖；拒绝不存在的引用和依赖环，不引入并行执行。这是新受控运行安全规则，不得丢失已有事件和脚本结构。
- MCP 支持完整 events 树读写往返与既有 legacy steps；两种输入互斥，未知节点明确拒绝，不能静默截断。读流程时返回 revision 及完整事件树。完整事件树更新必须携带 expected revision；名称等局部更新不重建步骤。已提供的 event、step 和逻辑步骤 ID 保留，新增节点才分配新 ID。legacy steps 未提供 ID 时按显式替换序列处理，不能根据位置猜测新旧步骤身份；包含条件或循环的流程拒绝用 legacy steps 覆盖，提示改用完整事件树。
- 兼容旧客户端未传 revision 的 legacy 更新，但必须串行校验并保存，不能声称其具备用户确认后的并发保护；本期 UI 与新 MCP 调用方均携带 revision，过期返回冲突且不写入。无论更新方式，当前 Run 都不会无提示采用新的 Flow 结构，恢复前始终校验本次审阅的 API revision。
- MCP 使用现有 enabled、项目允许列表、write 和 execute 控制：创建及更新不弱化写入限制，启动要求 execute，查询要求只读权限；每次控制与继续重新校验。method、origin、环境、脚本或文件范围超出原授权时需用户确认。MCP 权限撤销后阻止由 MCP 发起的 Run 后续步骤，UI 仍能停止该 Run。

## Testing Decisions

- 测试可观察行为、真实请求和持久化结果，不测试内部函数调用或镜像实现。主要通过一个高层公开流程入口，使用真实临时项目存储和 loopback HTTP 服务完成端到端测试；补充实际 MCP 适配测试和少量 Electron 交互测试。用户已确认此测试边界。
- 使用两个环境的不同 loopback 地址捕获请求，证明脚本变量与请求一致；延迟响应精确控制暂停，证明当前逻辑步骤完整结束、暂停后无后续请求、保存预览及手动继续。
- 覆盖同一 API 多次引用、运行变量保留、循环内恢复不重放、重复继续幂等；覆盖保存失败、接口删除、并发 revision 冲突及 input 覆盖冲突均阻止不安全恢复。
- 覆盖失败依赖与独立步骤、脚本和断言失败、201 且断言通过、结果未知和无自动重试、MCP 权限收紧、异步查询、旧同步接口、进度和报告版本切换；验证取消、重复启动幂等及中断后的部分结果。检查存量条件、循环及脚本行为。
- 至少一例通过真实 TCP 或 stdio MCP 链路；参考现有流程登录/token 的真实请求测试、MCP bridge 和 callTool 测试、保存 revision 通知测试，以及 Electron 临时项目交互测试。运行现有 typecheck 与 build。
- 现有测试参照：[流程与 MCP smoke](../../scripts/smoke.ts)、[接口保存和通知回归](../../scripts/client-sync-smoke.ts)、[Electron 临时项目交互](../../scripts/ui-smoke.cjs)。新增测试复用这些基础设施，使用可控响应和状态事件同步，不靠长时间 sleep 碰运气。

## Out of Scope

内置 Agent runtime、对话及会话、模型 provider 或 SDK、完整候选版本系统、未保存 Agent 草稿集成、远端操作回滚和自动重试不属于本规格的交付范围。

## Further Notes

本轮通过 to-spec 发布可编码规格；另一个任务负责内置 Agent。外部 MCP 已可承担编排角色，不再把等待内置 Agent 作为本功能前置。Execution Flow、Run、Execution Snapshot 与 Agent Plan 分别使用术语表定义；报告中记录的版本用于追溯请求依据，不保证服务端返回可复现。
