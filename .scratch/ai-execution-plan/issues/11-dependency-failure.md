# 11: 显式依赖与失败传播

**What to build:** 在完整 Flow 事件树中表达和验证依赖，并让受控 Run 对失败按依赖安全推进；失败阻塞不同于用户手动暂停。

**Blocked by:** 02: MCP 完整事件树与修订并发；04: 异步启动与查询 Run

**Status:** ready-for-agent

- [ ] UI 与 MCP 可保存、读取显式依赖；不存在的引用和依赖环被拒绝。
- [ ] 无法证明独立时按保守序列阻塞；只有显式声明可证明独立的步骤继续，不扫描脚本猜依赖。
- [ ] 不引入并行执行或自动重试；失败阻塞状态与用户暂停可区分。
- [ ] 请求错误、接口或步骤脚本错误、显式断言失败均计为失败并影响依赖步骤。
- [ ] HTTP 201 在显式断言通过时可成功，不套用非 200 必失败规则。
- [ ] 保留已有事件树、循环和脚本，不因失败策略丢失数据。
- [ ] 真实存储和 loopback/MCP 测试验证依赖阻塞、独立继续、失败及成功规则。
- [ ] 执行本票相关类型检查及 build，保持现有检查通过。
