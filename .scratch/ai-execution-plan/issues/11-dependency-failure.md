**What to build:** 在完整 Flow 事件树中表达和验证依赖，并让受控 Run 对失败按依赖安全推进；失败阻塞不同于用户手动暂停。

## Answer

通过 `FlowEvent.depends_on` 保存显式依赖：省略表示保守顺序，空数组表示明确独立，非空数组引用 event ID。UI 提供依赖策略和步骤选择；MCP 完整事件树保持相同合同。保存时校验不存在引用及显式、隐式顺序和逻辑分组构成的依赖环，拒绝后不写入。

执行保持串行且不重试。未证明独立的步骤遇前序失败进入 `blocked`；同一逻辑步骤不能绕过组内失败，外部依赖需要完整逻辑步骤成功。已成功进入的独立组保留其前置、接口和后置执行。接口与步骤脚本错误、接口与步骤断言失败纳入失败传播；HTTP 201 在断言通过时成功。结果和运行状态显式展示依赖阻塞，区别于跳过和用户暂停。
