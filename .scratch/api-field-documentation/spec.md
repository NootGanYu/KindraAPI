# 请求与响应字段文档

Status: implemented
Date: 2026-11-01
Feature: api-field-documentation

## 已明确的目标

前端同事阅读接口文档时，能够知道请求与响应中各字段的含义、是否必填和枚举取值，并看到可理解的请求与响应示例。补齐响应体字段描述能力，同时解决分享文档中请求示例不足以说明参数的问题。

**主要使用场景：编码 Agent 通过 MCP 维护接口文档。** 用户通常在 Agent 编写业务代码的过程中，让 Agent 直接把接口信息写入 KindraAPI，人工在应用内编辑较少。因此 MCP 是主要编写入口，应用编辑是补充；验收必须覆盖 Agent 从创建、补充到更新接口文档的完整过程，不能把 MCP 当作 UI 完成后的附属接线。

## 实现前的代码事实

- 请求 JSON 字段编辑已使用 `BodyModel.field_docs`，支持类型、必填和描述；字段文档类型尚无显式枚举、默认值和可空性。
- 普通请求参数 `Param` 有描述、类型和发送启用状态，但没有独立的必填、枚举属性。发送启用状态不是必填规则。
- `ResponseExample.expect.schema` 已预留，但响应面板、分享页及 OpenAPI 导出尚未把它作为字段文档消费。
- 分享页的「查看示例请求」消费 `ResponseExample.request` 调用快照，快照只有方法、URL、请求头和请求体，没有独立的 Query 参数或字段说明。
- URL 编辑与 Query 参数表分别保存；直接写在 URL 中的查询参数不会自动进入参数表。它可以被正常发送，但可能没有独立的文档字段行。
- 截图中的 GET 查询参数 `id` 位于 URL。截图底部的 `{}` 不能证明 Query 参数缺失，也不能证明该请求必须有 JSON 请求体。
- 已有 ADR-0001 规定模型引用实时解析，生成 JSON 只作为最近一次预览结果；后续设计需要尊重该约定，或明确记录改变理由。
- 常规保存接口时，若存在真实发送记录且没有模型引用响应示例，渲染层 `store.ts:307` 会把整个响应示例列表替换为单个实时响应；MCP 的简化响应写入与保存执行响应也会整体替换。字段文档的持久保留必须覆盖这些写入路径。
- 响应面板仅选择默认或首个示例；OpenAPI 导入仅选首个成功响应，导出按状态码赋值会覆盖同状态码的前一个示例。

## 已确认决策（第一轮）

1. **字段文档独立于调用示例。** 从接口定义生成完整的请求参数表与响应字段表，即使接口从未发送过也能形成文档。Query、Path、Header、Cookie 和 Body 分开展示；调用示例另行展示。没有请求体时明确显示“无请求体”。
2. **字段信息完整覆盖。** 支持字段名、类型、描述、请求必填或响应必有、可为 null、默认值、示例值，以及枚举值和各个值的业务含义。必填或必有与可空性分别表达。
3. **不从示例猜测业务规则。** 旧接口保留已有说明与明确约束；缺少的描述、必填规则和枚举信息标记“待补充”，由维护者完善。已有数据模型或导入文档中的明确规则需保留。本次未要求代为补录现有业务接口文档。

用户已逐项确认以上三点。业务规则不能由一次 JSON 示例或发送启用状态推断。

已记录为 [ADR-0005](../../docs/adr/0005-field-documentation-independent-of-examples.md)，相关术语见根目录 `GLOSSARY.md`。

## 已确认决策（第二轮）

4. **本期仅维护成功响应。** 不扩展多种失败或业务错误响应的编写能力。已有历史响应数据不因范围收窄而自动删除。
5. **显式保存响应示例。** 取消发送后保存接口时自动覆盖原有响应示例的行为。需要将真实响应保存为示例时，由用户或 Agent 明确选择新增或更新；更新时保留字段说明、必有规则与枚举，不能因一次响应缺少字段就删除定义。
6. **模型规则统一继承。** 接口引用数据模型时继承其字段说明和约束，模型修改同步反映到引用处；需要单独修改时，先解除引用并保留完整字段定义，不维护隐式的接口局部覆盖。
7. **全链路保留字段文档。** 覆盖应用编辑、在线分享、离线 HTML、Markdown、现有 OpenAPI 导入导出和 MCP 读写。MCP 为主要编写入口。
8. **URL Query 仅补文档提取。** 自动提取直接写在 URL 中的查询参数，并与显式参数表中的已有说明关联。当前请求编辑和发送行为保持不变，本期不实现 URL 与 Query 编辑器的双向同步。
9. **发送启用与文档分离。** 调试时取消勾选发送的参数仍展示在字段文档中；参数表表达接口完整定义，具体请求示例表达实际发送内容。

用户明确调整第 4 项为仅成功响应，并确认第 5–9 项按建议执行。

## 已确认决策（第三轮）

10. **增量维护与显式删除。** Agent 只修改明确提交的内容，未提交的说明和规则保留；删除字段、清空规则必须明确表达。重复提交不得重复创建接口或误删已有文档。
11. **缺项提醒，错误拒绝。** 业务说明暂缺时允许保存，并通过 MCP 返回具体字段的待补充清单；不合法或自相矛盾的定义拒绝写入并指出原因，已有有效数据保持完整。
12. **先做好单接口完整写入。** 单次 MCP 调用可写入一个接口的完整请求定义、成功响应字段文档及示例，不需要先执行接口或创建共享模型。多接口由 Agent 逐个调用，保留现有 OpenAPI 批量导入，本期不另加多接口批量写入工具。

用户已逐项确认，并提供当前已安装应用的 MCP 配置，明确授权查看、修改和验证本机数据。实现与自动化验证先使用隔离数据；现有业务项目仅用于确认兼容性，避免无必要的业务数据改动。

## 验收重点（已有决定推导）

- 仅用 MCP 创建一个从未执行过的接口，即可在分享文档中看到请求参数与成功响应字段的完整说明和示例。
- 请求和成功响应均覆盖嵌套对象、数组元素字段、必填或必有、可空、默认值以及带含义的枚举。
- 对同一接口再次写入或调试发送后，已有字段规则不被意外删除或被实时响应替代。
- URL 中直接填写的查询参数出现在参数文档中；调试未启用的参数仍可查阅定义。
- 缺失规则明确显示待补充；已有模型、导入数据、导出文件和 MCP 返回不丢失已知规则。
- 真正无请求体与显式的空 JSON 对象分别展示，不能依据 GET 方法或字符串 `{}` 一概判断。

## 实现与验收记录

- `upsert_api` 一次编写接口；以 `source_key` 幂等定位，字段按路径增量合并，显式 `remove` / `unset`，缺项清单与原子校验。
- 请求和成功响应共用字段规则；应用编辑、分享、离线 HTML、Markdown 与 OpenAPI 使用同一套定义。新增成功示例和更新捕获示例均为显式操作。
- 查询参数按接口定义展示；无请求体与历史调用中的 `{}` 分开处理。实查本机「农户审核详情」发现 Query 表已有 `id`，请求模式为 `none`，旧调用快照却保存了 `{}`。

- `npm run smoke` 全量回归通过；`npm run typecheck` 通过。界面回归 15 项通过，并在浏览器检查分享页排版。
- 发行版本为 0.2.4；提供 Windows 安装包。现有安装版和业务数据未被自动替换。
- 新打包版在隔离数据目录启动后，使用用户原安装目录中的 `mcp-stdio.cjs` 完成 `tools/list`、`upsert_api` 和 `get_api_detail` 的真实 stdio 验证，71 个工具可发现，字段枚举及含义写入回读一致。测试进程已关闭。
