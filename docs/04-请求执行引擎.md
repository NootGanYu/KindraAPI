# 04 · 请求执行引擎

> 核心结论：Apipost 没有自己重写 HTTP 协议栈，而是把自有模型转换成
> **postman-collection**，交给 **postman-runtime** 执行。
> 脚本、断言、变量、重定向、代理、证书、HTTP/2 等能力全部来自 Postman 生态。

---

### 1.2 test_events（事件）

```json
[
  {
    "event_id": "1f...",
    "test_id": "1f...",
    "type": "api",                 // api | sample | sse | request | script | assert | assert_visual | sql | wait | if | assert_if | begin | loop | multi_if
    "enabled": 1,

      "project_id": "...",

        "request": { ... }
      }
    }

```

【事实】实际判定条件（`analysis/pretty/842216.js:1133`）：

```
auto_sync > 0 || scene ∈ { "http_request", "get_parsed_request" }
  → 从 option.collection 取接口实体
否则
  → 使用事件内联的 apiData
```

即 `http_request` / `get_parsed_request` 会**强制**走 collection，即使
`auto_sync <= 0`。旧版“auto_sync != 1 就用 apiData”是错的。

- `scene = "http_request"` 时只执行第一个事件。

## 2. 执行主流程

```
run(test_events, option, emit)
  ├─ scene = http_request
  │    └─ executeEvent(firstEvent, option, emit, state, results)
  │         └─ handler[type](event, option, emit, state, results)
  │              └─ P(): 转 postman-collection → postman-runtime
  │                   └─ done() → emit({action:"request", data: ...})
  └─ scene = auto_test
       ├─ 按 iterationCount 复制事件列表
       ├─ iterationEvent(events...)
       │    ├─ 顺序执行
       │    ├─ 断言失败 / 请求失败 → 默认**继续**（`ignore_error` 默认 1）；
       │    │  置 0 才中断（见 05 §2.1）
       │    └─ 支持 children / if / loop / begin
       └─ 完成后 emit({action:"complete", data: report})
```

### 2.1 事件类型 → 处理器

| type | 行为 |
|---|---|
| `api` / `sample` / `sse` / `request` | 走 HTTP 执行（`P`） |
| `script` | 把脚本塞进 `pre_tasks.customScript` 执行 |
| `assert` | 同上，但结果按断言处理 |
| `assert_visual` | 转成 `pre_tasks.type = "assert"` 的可视化断言 |
| `sql` | 转成 `pre_tasks.type = "database"` |
| `wait` | 读取 `event.data.sleep`（毫秒）；不支持裸数字 |
| `if` | 条件判断，条件为真执行 children |
| `begin` | 无条件执行 children |
| `loop` | 循环执行 children（数据遍历/提取/变量列表） |
| `assert_if` | 先执行断言，再按结果决定是否执行 children |
| `multi_if` | 多条件分支 |

> 【事实】运行时 handler 表只有上表 14 类，**没有 `case`**
> （`analysis/pretty/842216.js:2964-3415`）。`case`（接口用例）是容器与
> 报告维度，不是 send 运行时可执行事件；旧版表里的 `case` 已删除。
> 是否由渲染层/后端预展开未能确认，复刻时不要依赖该类型。

## 3. 模型转换（Apipost → Postman）

### 3.1 解析继承链

1. 从 `data.target_id` 找到接口实体。
2. 沿 `parent_id` 向上收集所有祖先，直到 `"0"`。
3. 根使用 `option.project.request`（即 `global_params.json`）。
4. 按 header/query/cookie/body 合并，子级优先。
5. `auth` 为 `inherit` 时向上取第一个非 inherit 的认证。
6. `pre_script/test/pre_tasks/post_tasks` 向上拼接。

### 3.2 URL 与前缀

- 优先用 `event.pre_url`（旧版漏了事件层，只写了 `data.pre_url`）。
- 否则用最终 `server_id` 在 `env.env_pre_urls` 的**值**中查找
  `server_id` 匹配项，取 `uri`（不是 `env_pre_urls[server_id]` 下标）
  （`analysis/pretty/842216.js:1305`）。
- 拼接时用 `smartUrlJoin`：任一参数已带协议头（`http://` / `https://` 等）
  时**整体返回**，前缀被忽略（`:654-656`）。因此绝对 URL 会短路前缀拼接。
- 支持 `{{variable}}` 占位；变量替换分三阶段（建模期 `initVarReplacedUrl`、
  `beforeRequest`、条件/循环期），不是只有一处。

### 3.3 路径参数

- `request.restful.parameter[]` 中 `is_checked > 0` 的项 → `url.variable[]`。
- 路径里的 `{id}` 会转成 `:id`（Postman 风格），再由变量绑定真实值。

### 3.4 查询参数

- `request.query.parameter[]` 中 `is_checked > 0`。
- `request.query.query_add_equal` 控制空值是否输出 `key=`。
- `value` 为空且 `schema` 存在时，用 JSON Schema 生成值。
- 环境 id 为 `"2"` 时自动追加 `target_id` 查询参数（历史兼容逻辑）。

### 3.5 请求体模式

| `body.mode` | 转换结果 |
|---|---|
| `none` | 无 body |
| `raw` | `body.mode = "raw"`，`options.raw.language` 由内容类型决定 |
| `json` / `xml` / `javascript` / `plain` / `html` | 统一走 raw，语言由 mode 或 `options.raw.language` 决定 |
| `urlencoded` | `body.mode = "urlencoded"` |
| `form-data` | 内部映射为 `body.mode = "formdata"`；`field_type === "file"` 的项作为文件 |
| `binary` | `body.mode = "file"`，`file.src = data_url`（或缓存文件） |
| `msgpack` | 编码为二进制，`Content-Type: application/msgpack` |

> 【事实】Apipost 侧的枚举是 `form-data`（带连字符），postman 侧才是
> `formdata`；文件字段判定用 `field_type`，不是 `type`
> （`analysis/pretty/842216.js:1690-1704`）。

`binary.data_url` 是 base64 data URL；发送前会落成临时文件（`base64toCacheFile`）。

### 3.6 认证映射

Apipost 认证 → Postman auth：

| Apipost | Postman |
|---|---|
| `kv` | `apikey`（in/header/query + key/value） |
| `bearer` | `bearer.token` |
| `basic` | `basic.username/password` |
| `digest` | `digest`（字段重命名 + 默认 `disableRetryRequest=false`） |
| `oauth1/oauth2/hawk/awsv4/ntlm/jwt/asap/edgegrid` | 同名，字段直接透传 |
| `noauth` | `noauth` |
| `inherit` | 继承父级 |

### 3.7 Cookie

- `option.cookies.switch > 0` 时，把全局 Cookie 和接口 Cookie 合并：
  ```json
  { "key": "...", "value": "...", "domain": "...", "path": "/", "expires": "...", "maxAge": 3600, "secure": false, "httpOnly": false, "sameSite": "strict" }
  ```
- 接口级 `request.cookie.parameter` 会覆盖同名全局 Cookie。

### 3.8 变量作用域与优先级

**Postman 运行时作用域**（高 → 低）：

1. `localVariables`（Apipost 把所有变量先塞这里）
2. `data`（迭代数据）
3. `environment`
4. `globals`

> Postman 原生还包括 `collectionVariables`（位于 `environment` 与 `globals` 之间）；
> Apipost 的请求模型没有 collection 作用域，因此转换层不创建它。

**Apipost 自己的替换顺序**（`beforeRequest`）：

```
getInsideVariables()            // 内置变量
  ← globals
  ← environment
  ← variables
```

即 `variables > environment > globals`，内置变量先垫底。

### 3.9 内置变量

支持 `{{$...}}`：

- 随机类：`$natural $integer $float $character $range $date $time $datetime $now $guid $increment`
- 文本类：`$first $last $name $cfirst $clast $cname $title $ctitle $paragraph $cparagraph $sentence $csentence $word $cword`
- 网络/身份：`$url $protocol $domain $tld $email $ip $region $province $city $county $zip`
- 账号/媒体：`$username $user_name $nickname $nick_name $avatar $icon $img $photo $pic $description $id $userid $user_id $articleid $article_id`
- 手机：`$phone $mobile $telephone`
- 时间/数值：`$timestamp $microTimestamp $randomInt $randomFloat`
- 颜色：`$color $rgb $rgba $hsl`（`analysis/pretty/842216.js:105-108`）

自定义函数：`option.custom_functions = { name: body }`，以 `function name(text) { body }` 形式注入脚本环境。

## 4. postman-runtime 配置

```js
{
  requester: {
    strictSSL: false,
    protocolVersion: "http1" | "auto" | "http2",
    timings: true,
    verbose: true,
    implicitCacheControl: true,
    implicitTraceHeader: false,
    followOriginalHttpMethod: <bool>,
    followRedirects: <bool>,
    maxRedirects: Math.max(system_configs.max_redirect_time, 5),
    extendedRootCA?: "<path>"
  },
  timeout: { request: <send_timeout>, script: 0, global: 0 },
  delay: { item: 0, iteration: 0 },
  iterationCount: 1,
  fileResolver,
  data: [ iterationData ],
  environment: VariableScope,
  localVariables: VariableScope,
  globals: VariableScope,
  systemProxy: async (url, cb) => { ... },   // 顶层，不在 requester 内
  certificates: CertificateList              // 顶层，不在 requester 内
}
```

### 4.1 HTTP 版本选择

```
protocol = request.protocol || "http/1.1"
if protocol == "http/1.1" || target_type == "sse" || protocol 为空 → "http1"
else if protocol == "auto" → "auto"
else → "http2"
```

### 4.2 代理

优先级逻辑（来自**顶层** `options.systemProxy`，
`analysis/pretty/842216.js:1893`）：

1. `system_configs.proxy.type == 1`：显式代理
   - 受 `bypass`（glob 匹配）和 `protocols` 限制
   - 可带 basic auth
2. `proxy.type == -1`：环境变量代理
   - 先看 `NO_PROXY`
   - 再看 `HTTP_PROXY` / `HTTPS_PROXY`
   - Electron 下还会调用 `session.resolveProxy(url)` 读取系统代理
3. 否则直连

### 4.3 证书

- CA：`system_configs.ca_cert.open > 0` 且 path 非空 → `extendedRootCA`。
- 客户端证书：按 `host:port` 匹配，支持 `key/crt/pfx` 文件或 base64。

## 5. 脚本沙箱（pm / apt）

【事实】`pre_tasks` / `post_tasks` 里的 `customScript` 由
**`postman-sandbox` / `uvm`** 执行（`analysis/ext/send/index.js`）；只有
`callFunction` 与部分内部脚本使用 Node `vm`。两者不要混为一谈。注入：

- Postman 兼容：`pm.environment / pm.globals / pm.variables / pm.request / pm.response / pm.test / pm.expect / pm.sendRequest`
- Thunder Client 兼容：`tc.*`
- Apipost 扩展：`apt.*`
- 库：`lodash`、`mockjs`、`jsonpath`、`xml2json`、`JSON5`、`CryptoJS`、`apipost-tools`
- 自定义函数：`function name(text) { ... }`

### 5.1 变量读写

| 操作 | API |
|---|---|
| 环境变量 | `pm.environment.get/set` |
| 全局变量 | `pm.globals.get/set` |
| 临时变量 | `pm.variables.get/set` |
| 提取变量（可视化） | `pre_tasks` 类型 `pickVars`（源码中未见 `extract`） |

脚本改动会回写到运行时变量表，并在 `currentVariables` 中记录 `start/current` 与作用域。

### 5.2 自定义函数执行入口

主进程还提供 `apt://localhost/proxy/callFunction`：

```json
{ "context": "return text.toUpperCase();", "text": "abc" }
```

在 `vm` 中执行，3 秒超时，返回 `{ text, value }`。

```json
{
  "log": {
    "version": "1.2",
    "creator": { "name": "Custom Node Request to HAR Converter", "version": "1.0" },
    "entries": [
      {
        "request": {
          "method": "GET",
          "httpVersion": "HTTP/1.1",
          "url": "http://...",
          "headers": [ { "name": "...", "value": "..." } ],
          "queryString": [ { "name": "...", "value": "..." } ],
          "postData": {
            "mimeType": "application/json",
            "text": "...",
            "params": []
          },
          "headersSize": -1,
          "bodySize": -1
        },
        "response": { "status": 200, "statusText": "OK", "headers": [], "content": { "size": 0, "mimeType": "application/json" } },
```

## 9. 其他协议

### 9.1 WebSocket

- 渲染层先建立连接：`/proxy/v2/websocket`
- 服务端 SSE 事件：`connected` / `received` / `ping` / `error`
- 发送消息：`/proxy/v2/websocket_send`
- 连接保存在主进程 `global.websocketStore[target_id]`
- 20 秒 ping 保活

### 9.2 Socket.IO

- `/proxy/v2/socketio`、`socketio_send`、`socketio_update_event`
- 支持 event、ack、type、参数更新

### 9.3 gRPC

- `grpc_proto`：从 `.proto` 解析服务/方法
- `grpc_reflection`：服务端反射
- `grpc_request`：单次调用
- `grpc_request_sse`：服务端流
- 支持 unary / server_stream

### 9.4 TCP

- `tcp`：`ConnectAndSendMessage(data)`，返回响应字符串

### 9.5 数据库

- `query` / `test_connection`
- 支持 MySQL / SQL Server / ClickHouse / DM / PostgreSQL / Oracle / Redis / MongoDB / GoldenDB
- 连接配置来自 `option.database_configs` 与项目 `db_link`

## 10. 复刻建议

如果只是「调用接口 + 记录响应」：

1. **直接依赖 postman-runtime + postman-collection**，可以省掉 90% 的协议细节。
2. 先把 Apipost 模型转成 Postman 模型，再执行；不要自己实现变量/脚本/断言。
3. 用 `PreparedRequest` 或 HAR 作为「响应记录」的稳定中间格式。
4. 超时、重定向、代理、证书都从系统配置读，避免写死。
5. 对失败请求也生成完整的 request 快照（便于复盘）。

关键坑：

- `{{var}}` 的优先级与替换时机（pre-request 前 vs 发送前）。
- header 名大小写不敏感合并。
- 空值参数是否输出 `key=`。
- 重定向后方法是否保持（POST → GET）。
- 二进制/大响应不要直接塞进 JSON 历史，落文件 + 引用。
- SSE / WebSocket 是长连接，不能用一次性 JSON 响应模型。
