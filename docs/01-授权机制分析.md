# Apipost 单机版授权机制分析（架构层）

> 分析对象：`/Applications/Apipost单机版.app`（`com.apipost.offline.fe.desctop.cn.8.x`，版本 2.0.0，Build 2026-10-10）
>
> **范围声明**：本文只描述授权系统的架构、状态机、数据流与信任边界，用于理解产品设计。
> 不包含、也不会提供任何绕过、破解、补丁、密钥生成或修改授权状态的方法。
> 如需长期使用，请通过厂商的离线授权 / 续费渠道获取 License。

---

## 1. 模块位置与保护方式

授权逻辑全部在主进程，且被 **bytenode** 编译为 V8 字节码（`.jsc`），发布包中不提供明文 `.js`：

```
Contents/Resources/app/utils/
├── license/
│   ├── index.jsc       # 状态机 + IPC 入口 + 定时巡检 + 广播
│   ├── verify.jsc      # License 数据解密与签名校验
│   ├── store.jsc       # 持久化、防回拨、多副本、系统级锚点
│   └── deviceId.jsc    # 设备唯一标识
├── fileDB.jsc          # 本地文件数据库（也被字节码化）
└── .bytecode-manifest.json   # 记录了被编译的文件清单
```

主进程对授权的接入只有一次 `init`，但入口本身还做 bytenode 注册、窗口、
协议、文件 DB 等（`main.js:16-18` 先 `require("bytenode")`）：

```js
// main.js
const licenseManager = require("./utils/license");
...
licenseManager.init(ipcMain);
```

渲染层（`work.asar`）不允许直接读写授权数据，只能通过 IPC 调用。

### 为什么这样做

- 隐藏校验细节，避免明文逻辑被直接阅读；
- 把“状态权威”放在主进程，渲染层即使被调试也无法单独改变授权结果；
- `fileDB` 一起字节码化，避免通过改写本地数据文件绕过。

## 2. 状态机

`index.jsc` 中可见的状态与常量：

| 状态 | 含义 |
|---|---|
| `trial` | 7 天免费试用中 |
| `trial_ended` | 试用结束，未绑定 License |
| `bound` | 已绑定且未过期 |
| `expired_bound` | 已绑定但已过期 |
| `read_only` | 只读模式（仍可浏览本地数据）；【事实】`index.jsc` 导出的是 `isReadOnly()` 函数，动态加载确认存在；是否作为状态字符串返回未确认 |

可见常量：

- 【事实】`DAY_MS = 86400000`、`CLOCK_TOLERANCE_MS = 300000`
  （动态加载 `store.jsc` 读取导出值）。
- `TRIAL_DAYS`：试用天数（界面文案为 7 天；常量名可见，**数值未导出**）
- `RENEW_HINT_DAYS`：到期前提醒天数（**数值未导出**）
- `WATCH_INTERVAL_MS`：定时巡检授权状态的间隔（**数值未导出**）
- `PERSIST_MIN_INTERVAL_MS`：持久化最小间隔（**数值未导出**）

> 动态探针已确认 `license/index.jsc` 导出
> `init / getPublicState / activate / unbind / isReadOnly`，
> `store.jsc` 导出 `load / save / DAY_MS / CLOCK_TOLERANCE_MS`，
> `deviceId.jsc` 导出 `getDeviceId`。其余常量在闭包内，无法通过导出读取。

状态对象对外暴露的字段（`getPublicState`）：

```
bound, expired_bound, remainingDays, renewHint,
validFrom, validTo, boundAt,
licenseKeyMasked, licenseEmail,
trial, trial_ended, trialRemainingDays
```

`licenseKeyMasked` 说明界面只展示打码后的密钥，不展示原文。
【事实】`verify.jsc` 的 `maskKey` 对短串原样返回，对长串保留前 4 位与
后 4 位、中间替换为 `•••••••••`（动态探针确认）；空串返回 `""`。

### 状态流

```
首次启动
  └─> trial（写入 trialStart；试用期内功能可用）
        ├─ 绑定成功 ─> bound ─(到期)─> expired_bound
        └─ 7 天结束 ─> trial_ended

trial_ended / expired_bound
  └─> 渲染层进入只读/限制模式，可浏览本地数据，但禁用调试、Mock、压测等能力
```

> 【推断】旧版写成“任意非 bound 状态都只读”过宽：界面文案只说
> “绑定后可解锁完整使用期限”，试用期内应仍可调试。需以 UI 实测为准。

界面文案也印证了这一点：

- “当前为试用模式，剩余 {{n}} 天试用期。绑定 License 后可立即解锁完整使用期限。”
- “7 天免费试用已结束，绑定 License 后即可继续使用调试、Mock、压测等功能。本地项目数据不受影响。”
- “你的 Apipost 单机版授权已到期…**本地项目数据不受影响**”

## 3. IPC 契约

`preload.js` 暴露给渲染层的授权 API：

```js
license: {
  getState: () => ipcRenderer.invoke("license:getState"),
  activate: (key) => ipcRenderer.invoke("license:activate", key),
  unbind: () => ipcRenderer.invoke("license:unbind"),
  onChanged: (cb) => {  // 订阅主进程推送
    ipcRenderer.on("license:changed", listener);
    return () => ipcRenderer.removeListener("license:changed", listener);
  }
}
```

行为要点：

- **状态权威在主进程**：`getState` 每次返回主进程计算后的结果，渲染层不缓存为权威。
- **单向广播**：主进程在激活 / 解绑 / 到期跨状态时 `webContents.send("license:changed", state)`。
- **只读入口**：没有暴露任何“直接写授权文件”的接口。
- `index.jsc` 内还有 `startWatcher` / `watchTimer` / `lastBroadcastState`，说明有周期性巡检，用于处理“运行过程中到期”。

## 4. License 数据的结构

`verify.jsc` 中可见的字段名：

```
payload
 ├─ seatId
 ├─ deviceNumber        // 绑定的设备标识
 ├─ email               // 授权邮箱（界面展示用）
 ├─ activatedat / validFrom
 └─ expiryat / expiresAt
metadata
ciphertext
```

校验流程（概念层）：

1. 解析 License Key，得到 Base64URL 编码的密文与元数据；
2. 使用内置 AES 密钥做 **AES-256-GCM** 解密（`createDecipheriv("aes-256-gcm")`，带 nonce 与 authTag）；
3. 使用内置 **Ed25519** 公钥对元数据做签名校验（`crypto.verify`，曲线标识 `302a300506032b6570032100` 为 Ed25519 SubjectPublicKeyInfo 前缀）；
4. 校验：
   - `deviceNumber` 与当前设备是否一致（`sameDevice` / `device_mismatch`）；
   - `expiresAt` 是否已过期（`expired`）；
   - 时间字段是否合法（`isFinite`、`toMs`）。

错误码可见：`invalid`、`key_expired`、`device_mismatch`、`expired`
（渲染层另有 `activate_key_expired`）。

> 【事实】动态探针调用 `verifyKey`：空串/短串/非法格式均返回
> `{ok:false,error:"invalid"}`。License Key 的分隔符、段序、
> nonce/tag 长度与签名覆盖范围**无法从导出接口确认**，本文不做臆测。

### 设计含义

- **非对称签名**：只有厂商私钥能签发，客户端只持公钥，因此本地无法伪造一张“看起来合法”的 License。
- **对称加密**：License 内容对用户不可读，避免被直接改字段。
- **设备绑定**：License 与 `deviceNumber` 绑定，换机需要重新绑定/解绑。

## 5. 设备标识（deviceId.jsc）

实现要点（字符串可见）：

- 基于 **node-machine-id** 的 `machineIdSync()`；
- 结果做格式化：转大写、按 8 字符分组（`(.{8})(?!$)`）；
- 有缓存与兜底：
  - 缓存文件：`<userData>/fallback-device.id`
  - 兜底：`crypto.randomBytes` 生成并落盘；
- 缓存存在时优先使用缓存，保证 machine-id 变化时授权不漂移。

---

## 6. 持久化与防回拨（store.jsc）

可见的持久化设计：

| 机制 | 说明 |
|---|---|
| 主文件 | `<userData>/license.dat` |
| 影子副本 | `shadowPath`，与主文件互为备份 |
| 系统级锚点 | macOS：`defaults read <OS_DOMAIN> <OS_KEY>`；Windows：`reg query <WIN_REG_KEY>`；另有 `homePath` 下的锚点文件 |
| 原子写 | `writeFileAtomic` |
| 损坏恢复 | `backupCorrupt`、`readFileSafe` |
| 时钟防回拨 | `CLOCK_TOLERANCE_MS = 300000`（5 分钟，动态导出确认）+ `lastSeenAt`；若系统时间倒退超过容差，会判定异常 |
| 写入节流 | `PERSIST_MIN_INTERVAL_MS`（闭包内，数值未导出） |
| 天级换算 | `DAY_MS = 86400000`（动态导出确认） |
| 完整性 | `encodeRaw` / `decodeRaw` / `canonicalJson` / `verifyRecord` / `deviceMatches` |

设计意图：

1. **多副本**：删掉单个文件不会重置试用；
2. **系统级锚点**：即使清空 userData，仍能在系统偏好/注册表中发现历史；
3. **防回拨**：把 `lastSeenAt` 持久化，时间倒退会被识别；
4. **设备一致性**：记录里的 `deviceMatches` 校验，防止拷贝他人授权目录。

## 7. 与渲染层的配合

从 `work.asar` 中可见的文案与逻辑：

- 未授权时进入 **read-only / 限制模式**；
- 提供“暂不激活，仅浏览本地数据”；
- 激活成功后广播 `license:changed`，界面刷新为 `bound`；
- 到期时提示续费，但明确“本地项目数据不受影响”。

即：授权只控制**功能开关**，不加密、不删除用户项目数据。

## 8. 信任边界总结

```
┌───────────────────────────────┐
│ Renderer (work.asar)          │  不可信：只展示，不能决定授权结果
│  - 调 license:getState        │
│  - 收到 license:changed       │
└──────────────┬────────────────┘
               │ IPC（白名单）
┌──────────────▼────────────────┐
│ Main Process                  │  可信：状态机 + 校验 + 落盘
│  license/index.jsc            │
│   ├─ verify.jsc (AES-GCM+Ed25519)
│   ├─ store.jsc  (多副本/防回拨)
│   └─ deviceId.jsc (机器绑定)
│  fileDB.jsc                   │
└──────────────┬────────────────┘
               │
     userData / 系统偏好 / 注册表
```

关键结论：

- 授权判定完全在主进程，且签名校验使用厂商私钥签发的数据，客户端无法离线伪造；
- 试用状态与机器绑定，并通过多副本 + 系统锚点 + 时间回拨检测提高“重置”成本；
- 渲染层不是信任边界，改前端不能改变授权结果。

## 9. 对“自研同类工具”的启示（非绕过）

如果你要复刻一个自己的 API 调试/记录/自动化工具，并不需要照搬这套授权：

- **功能与授权解耦**：授权只做功能开关，永远不要碰用户数据；
- **主进程权威**：任何安全/许可判定都放在主进程，前端只展示；
- **状态机 + 事件广播**：`getState` 拉取 + `changed` 推送，便于多窗口一致；
- **数据持久化**：原子写 + 备份 + 版本号，避免崩溃丢数据；
- **设备绑定（如需）**：非对称签名 + 设备指纹，客户端只持公钥。

> 再次说明：本文不提供任何绕过现有授权的手段。需要继续使用原软件，请走厂商授权渠道。
