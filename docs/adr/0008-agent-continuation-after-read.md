# 连续任务在批准槽位内延迟绑定读取结果

Status: accepted（2026-11-05）

模型常需要先读取接口或执行流程的真实定义，才能生成依赖这些内容的补丁，再采纳并测试。若在批准前就把定义发给模型，用户批准的是尚未看见具体范围的计划；若要求模型在首轮写死全部参数，则读取派生与“修改后立即测试”无法完成。

因此 Agent 计划同时支持静态与延迟绑定槽位：批准时固定操作、精确对象、环境、依赖、允许字段、来源步骤、脚本与文件指纹、额外请求额度和一次执行额度，但补丁参数可在获批读取返回后由模型生成。执行前仍按槽位复核有效差异与范围；扩大对象、操作、字段、来源或副作用必须暂停并生成新的授权版本，不先执行再报告。静态计划保持原有“首轮固定参数”的行为。

代价是计划格式、调度与恢复状态更复杂，且必须持久化每个槽位的授权版本与尝试状态；收益是模型能在用户已批准的具体范围内真正读取、派生、采纳与测试，而不会获得项目级任意编辑或执行权限。被否决的方案包括：批准前发送完整定义（泄露未批准范围）、仅靠提示词让模型预写补丁（无法读取派生）、以及为连续任务另建一套执行器（与既有权限、执行快照和双协议重复）。
