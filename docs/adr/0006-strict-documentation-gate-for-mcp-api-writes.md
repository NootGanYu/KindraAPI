# MCP 新建接口执行硬性文档校验

Status: accepted（2026-11-02）

MCP 是接口文档的主要编写入口。此前工具说明要求 Agent 填写接口说明、完整 URL 与字段规则，但服务端只把这些缺项放进 `documentation.issues`，接口仍会保存，Agent 可以忽略提示。结果是文档质量取决于调用方是否自觉。

本决策把新建接口的以下内容改为服务端硬性门槛：接口说明 `description`、完整 `http(s)` URL、每个已知请求参数与请求/响应字段的 `description`、`type`、`required`、`nullable`、`enum`；有枚举时必须提供逐项对应的 `enum_descriptions`。缺失任一项时整次写入被拒绝，已有数据保持不变。更新接口保持增量语义，只校验本次显式提交的字段，未提交的历史字段不追溯。

自动生成的系统 Header 不属于作者职责，不参与校验。引用数据模型的分支继续由模型定义校验负责，不把模型规则重复计算到接口上；模型自身的文档要求由已有的模型工具约束。

该选择牺牲了一次写入的宽容度，换取所有 Agent 在同一套规则下产出一致、可读的接口文档。无法确定业务含义或规则时，调用方应先向用户确认，不能从字段名或示例猜测，也不能以“待补充”状态写入新接口。相关背景与既有决策见 `.scratch/api-field-documentation/spec.md` 与 ADR-0005。
