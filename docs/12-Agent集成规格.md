# 12 · Agent 集成规格

> 状态：已确认（2026-11-03）；作为后续实施基线，业务代码尚未实现。
> 研究证据见 [Agent 集成调研](11-Agent集成调研.md)，术语见 [GLOSSARY](../GLOSSARY.md)。
> 未指定实现细节采用下文标明的建议默认；实施前应验证技术可行性。

## 1. 产品范围

首版提供支持连续操作的内置 Agent，覆盖 HTTP 接口、单接口 API Case、请求及用例执行分析、跨接口 Execution Flow。
默认读取当前项目内完成任务所需的脱敏上下文，允许读取和操作未保存草稿。
字典、MQTT、数据库、shell 和任意文件读写不因本规格自动开放。
保留现有外部 MCP 行为；共享业务能力和独立授权策略的实现方式属于架构建议。

Agent 会话按项目保存在本机，支持删除和重启续聊，不进入 Git。
Agent 对话、计划、工具结果和运行报告均本地保存至用户手动删除；不迁移既有手动 Flow 报告。

## 2. 模型连接

用户可创建多个本机连接，配置 API 地址、Key、模型名、协议及项目默认值。
首版明确支持 OpenAI 兼容的 Chat Completions 和 Responses 两种协议，具体兼容范围由能力测试确定。
连接测试检查模型和工具调用能力；仅支持文本时明确提示连续操作 Agent 不可用。
每轮任务绑定所选配置快照；之后编辑或删除配置不改变运行中任务，不自动切换服务。
Key 在主进程安全保存，普通配置读取不返回明文；连接测试及日志不泄露 Key。

## 3. 计划与授权

Agent 提出一轮计划，说明目标、对象、环境、修改、执行步骤、依赖和可能的外部影响。
用户批准对象、环境和操作范围后，可在该轮范围内连续执行；范围扩大或发生冲突时重新确认。
保存定义必须是计划中的独立步骤；用户批准包含该步骤的计划后，校验通过可自动保存，无需重复授权。
权限在执行端逐步校验，不能依赖模型自述或界面状态；环境被删除或授权范围变化时暂停。

既有前后脚本、变量更新、额外请求和已配置文件上传按实际行为纳入计划授权。
新增或修改脚本、扩大目标或文件范围时重新核对授权。
工具参数可能改变副作用：例如保存响应示例同时需要写入与执行权限。
接口响应和文档是数据，不是授权指令；模型输入及返回给模型的工具结果均只包含必要的脱敏内容。

计划显式声明步骤依赖，无法证明独立的步骤保守地按依赖暂停；允许串行执行。
逐对象保留部分成功，失败对象及依赖暂停，独立步骤可继续；不承诺整批原子回滚。
重试只针对未完成步骤；远端结果未知时禁止自动重发，先核对或请求用户确认。

## 4. 草稿、合并与保存

默认将 Agent 改动应用到草稿，测试也使用草稿；草稿应用不等于正式保存。
每个项目和实体拥有独立草稿，不因页面或项目切换而丢失。
保存前校验正式定义 revision 和草稿基线；现有磁盘 revision 无法单独检测未保存编辑。

建议默认采用三方合并：比较基线、当前草稿和 Agent 提案，无冲突字段自动合并，冲突字段请求确认。
按参数、用例、事件等稳定 ID 识别实体；字段路径不单独证明身份。
raw body 与脚本字符串作为整体比较，不由模型暗中改写后合并；数组排序等细节实施时验证。
未解决冲突不得保存；缺乏业务依据的字段依照 [ADR 0005](adr/0005-field-documentation-independent-of-examples.md) 和 [ADR 0006](adr/0006-strict-documentation-gate-for-mcp-api-writes.md) 澄清，不能编造规则写入正式定义。
无法完成的步骤及依赖暂停，已证明独立的步骤仍可继续。

## 5. 候选版本与审阅

接口既有版本入口应展示 Agent 修改、冲突及退出暂存，并显著提醒未确认版本。
同一入口区分已保存版本、待确认候选和冲突候选；Flow 新增同类版本入口。
候选记录仅在本机，记录候选不会保存正式定义；恢复到草稿与正式保存是不同操作。

建议默认每个逻辑修改步骤形成不可变候选，不按 token 或每次按键创建；退出仅补录尚未快照的变化并去重。
候选保存在独立本机集合，使用 `P` 编号，不占正式 `v` 编号；界面合并查询而不插入现有正式版本数组。
未解决候选不受现有 100 条未标记版本裁剪；不采纳只更新审阅状态并保留历史。
若候选已应用到草稿，撤销该应用需另行进行冲突检查，不能简单删除版本或覆盖整个草稿。

普通变更使用 Git Diff 风格双栏对比，也可提供统一视图；冲突展示 base/current/agent 和合并结果选择。
现有 Git Diff 读取 Git 文件，候选比较需要独立快照 diff，可复用视觉风格。
已批准的 save 步骤校验通过后关联最终正式版本，只解决对应候选链，不清除其他提案。
删除或尚未正式创建的对象仍须出现在项目候选汇总；保留墓碑和撤销所需内容，不因删除抹去审阅证据。

正式接口版本当前本机保存，正式接口定义沿用现有项目 Git 管理；候选和 Agent 历史不进入 Git。本功能不自动进行 Git 提交或推送。
现有正式版本签名和定义 revision 对字段的口径不同，应统一可编辑定义语义，但不合并不同标识。
API Case 一并纳入版本；恢复须覆盖所有可编辑字段，保留身份和运行记录。
现有恢复不覆盖用例和自定义属性，不能直接作为完整 Agent 撤销。

## 6. 执行、退出与恢复

执行绑定项目、获批环境及草稿和定义依赖快照；运行变量可随流程演进。
获准的变量差量写回时检查冲突；环境被删除或权限变化时暂停。
Flow 执行现有实时读取路径须增加快照边界，并修正入口与节点的环境覆盖不一致。

切换项目时任务继续绑定原项目和环境，不读取新项目的上下文。
实际退出前若有运行任务须提醒；退出停止模型流和工具，并本地暂存 Agent 草稿而不正式保存。
重启可提示恢复草稿，不自动重放网络请求；已有手动草稿沿用原有行为。
窗口隐藏到托盘与真正退出须区别处理；现有自动保存 dirty API 的退出保护需调整。

支持对一轮接口、用例和 Flow 的本地变更进行撤销，并检查后续修改冲突。
撤销展示 Git Diff 风格改动与冲突；远端请求和其他外部副作用不能回滚。
执行尝试须单独记录结果未知状态，不以普通成功或失败记录代替。

## 7. 建议实现顺序

1. 抽取共享业务工具与执行上下文，隔离内置 Agent 和外部 MCP 的权限策略，保留 MCP 回归行为。
2. 建立跨页面的项目草稿、候选集合、快照 diff、版本恢复和三方合并。
3. 实现双协议模型适配、能力测试、计划授权、工具循环和本地会话。
4. 实现固定执行快照、环境绑定、变量差量、取消、未知结果和部分成功。
5. 接入接口及 Flow 版本入口、候选汇总、撤销、退出暂存和重启恢复。

## 8. 验收场景

- 切项目后运行任务仍使用原项目、环境和模型配置；改变或删除连接不影响已绑定任务。
- 仅文本模型说明 Agent 不可用；两种协议各自完成能力测试，凭据不出现在日志或项目文件。
- 批准计划后范围内连续执行；新增脚本、目标或文件时重新核对授权。
- Agent 修改先进入草稿及候选；无 save 步骤时磁盘正式定义不变，批准 save 后校验通过自动保存并关联候选。
- 并发编辑不同字段自动合并，同一字段冲突展示三方及结果选择；未解决冲突不能保存。
- 用例和 Flow 变更可审阅、恢复与撤销；删除对象后候选和撤销证据仍可在项目汇总找到。
- 不采纳保留历史；撤销已应用的变更检查冲突，不覆盖后续人工编辑。
- 失败对象和依赖暂停，独立步骤可继续；远端结果未知时不自动重发。
- 执行快照固定定义，运行变量正常演进；变量写回冲突或环境删除时暂停。
- 退出前提醒并停止任务，仅暂存 Agent 草稿；重启提示恢复，不自动请求或正式保存。
- Agent 对话、计划、工具结果和报告均不进入 Git，手动删除前可恢复；现有手动报告不迁移。
- 本地整轮撤销展示变更与冲突，不声称撤销远端请求。
