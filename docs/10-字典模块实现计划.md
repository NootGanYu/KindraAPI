## 1. 范围

本轮实现字典模块的三块能力，并与 API、MCP 打通：

| 能力 | 本轮 |
|---|---|
| 数据字典 | 自定义 / 系统内置两个子标签；类型徽标；搜索；分页；内置描述总开关；增删改 |
| 数据模型 | 模型目录树、模型列表、可视化字段编辑器、Raw JSON Schema、预览；增删改查、复制、移动、拖拽排序 |
| 数据库管理 | MySQL 连接 CRUD、测试连接、读取表结构导入模型；SSH 配置只记录不执行 |
| API 联动 | 请求 Body 与响应示例引用模型，实时生成内容 |
| MCP | 模型 / 字典 / 数据库连接完整 CRUD；测试连接与导入表结构 |
| 内置描述联想 | 模型字段描述、API Header/Query/Path/Cookie/Body 表单参数描述 |

明确不做（后续里程碑）：非 MySQL、SSH 隧道、按环境覆盖连接、JSON Schema 文件导入导出、代码生成、智能导入、Mock 规则、OpenAPI 双向同步、字典导入/临时数据。

## 2. 数据契约

新增到 `src/shared/types.ts`，工厂函数放 `src/shared/factories.ts`。

### 2.1 数据字典

```ts
export type DictFieldType =
  | 'string' | 'number' | 'integer' | 'boolean' | 'object' | 'array'

export interface DictionaryEntry {
  id: string
  project_id: string          // 系统内置条目的项目为 "0"
  key: string                 // 参数名称
  field_type: DictFieldType
  description: string
  remarks?: string
  default_value?: string
  schema?: Record<string, unknown>
  created_at: string
  updated_at: string
}

export interface DictionaryEntryView extends DictionaryEntry {
  source: 'builtin' | 'custom'
}
```

- 自定义条目落盘 `<project>/settings/desc_list.json`，只存自定义。
- 系统内置条目是代码常量 `src/shared/dictionary.ts`，共 19 条（见 §6.1），不落盘。
- 总开关复用 `Project.is_describe_library`：`1` 开启、`-1` 关闭；写入 `project.json`。
- 类型只用于展示与联想，不参与请求发送。

### 2.2 数据模型

```ts
export type ModelType = 'model' | 'folder'

export interface ModelSchema {
  type?: 'object' | 'array' | 'string' | 'number' | 'integer' | 'boolean' | 'null'
  properties?: Record<string, ModelSchema>
  items?: ModelSchema
  required?: string[]
  default?: unknown
  enum?: unknown[]
  description?: string
  example?: unknown
  $ref?: string               // openpost://model/<model_id>
  'x-schema-orders'?: string[]
  'x-nullable'?: boolean
}

export interface DataModel {
  model_id: string
  project_id: string
  parent_id: string
  model_type: ModelType
  name: string
  alias?: string
  sort: number
  version: number
  status: number
  data: {
    description: string
    schema: ModelSchema
  }
  created_by?: string
  updated_by?: string
  created_time: string
  updated_time: string
}

export interface ModelSummary {
  model_id: string
  parent_id: string
  model_type: ModelType
  name: string
  alias?: string
  sort: number
  updated_time: string
}
```

- `schema` 是唯一事实来源；可视化编辑器读写它，`x-schema-orders` 保留字段顺序。
- 新模型默认 `{ type: 'object', properties: {}, 'x-schema-orders': [] }`。
- 字段的“允许为空”用 `x-nullable` 扩展；`required` 表示必填。
- 模型引用使用 `$ref: "openpost://model/<model_id>"`，只在模型 schema 内部使用。

### 2.3 数据库连接

```ts
export interface DbDefaultConfig {
  host: string
  port: number
  user: string
  password: string
  database: string
  charset?: string
}

export interface DbSshConfig {
  enable: -1 | 1              // -1 关闭，1 启用
  host: string
  port: number
  username: string
  password: string
  auth_type: 1 | 2 | 3        // 1 密码，2 私钥，3 密码+私钥
  private_key: string
  passphrase: string
}

export interface DbConnection {
  db_id: string
  project_id: string
  name: string
  type: 'mysql'
  remarks: string
  config: { default: DbDefaultConfig }
  ssh: DbSshConfig
  created_at: string
  updated_at: string
}
```

- 落盘 `<project>/settings/db_links.json`，数组结构，对齐原应用。
- 本轮只读写 `config.default`；不写 `config[env_id]`。
- `ssh` 字段完整保存（见 ADR-0002），测试连接与导入只走直连；`ssh.enable === 1` 时 UI 明确提示“SSH 隧道后续支持”。

### 2.4 API 引用

在现有类型上追加：

```ts
export interface BodyModel {
  // ...现有字段
  model_id?: string          // 引用模型；存在时 raw 仅作为最近生成结果
}

export interface ResponseExample {
  // ...现有字段
  expect?: {
    // ...现有字段
    model_id?: string

```

- `body.model_id` 与 `expect.model_id` 是引用事实来源。
- 删除模型后保留 `model_id`，渲染为失效引用（标红 + 解除入口）。
- 引用查找：扫描项目 API 的 `request.body.model_id` 与 `response.example[].expect.model_id`。

## 4. 主进程能力

### 4.1 `src/main/storage/store.ts`

### 4.2 MySQL

- 依赖：`mysql2`（promise API）。
- 连接参数：`host / port / user / password / database / charset`。
- 测试连接：`SELECT VERSION()`；超时 8 秒；失败返回可读错误。
- 表清单：
  ```sql
  SELECT TABLE_NAME, TABLE_COMMENT
  FROM information_schema.TABLES
  WHERE TABLE_SCHEMA = ? AND TABLE_TYPE = 'BASE TABLE'
  ORDER BY TABLE_NAME
  ```
- 列信息：
  ```sql
  SELECT COLUMN_NAME, DATA_TYPE, COLUMN_TYPE, IS_NULLABLE,
         COLUMN_DEFAULT, COLUMN_COMMENT, EXTRA
  FROM information_schema.COLUMNS
  WHERE TABLE_SCHEMA = ? AND TABLE_NAME = ?
  ORDER BY ORDINAL_POSITION
  ```
- SSH 本轮不建立隧道；启用时测试与导入直接报错提示“SSH 隧道后续支持”，避免静默走直连。

## 5. MCP 工具

完整 CRUD；写操作 `requires_write: true`，测试连接与导入 `requires_execute: true`。

| 工具 | 权限 | 说明 |
|---|---|---|
| `list_data_models` / `get_data_model` | 读 | 列表/详情，返回 schema 与引用数 |
| `create_data_model` / `update_data_model` | write | 名称、别名、目录、schema、描述 |
| `delete_data_model` | write | 必须 `confirm: true`；返回被引用接口列表；不自动清引用 |
| `list_dictionary_entries` | 读 | 支持 `source: builtin/custom/all` |
| `create_dictionary_entry` / `update_dictionary_entry` | write | 字段名、类型、描述 |
| `delete_dictionary_entry` | write | 仅自定义条目 |
| `list_db_connections` | 读 | **不返回密码/私钥/passphrase** |
| `create_db_connection` / `update_db_connection` | write | 接受完整连接配置 |
| `delete_db_connection` | write | 必须 `confirm: true` |
| `test_db_connection` | execute | 直连测试；SSH 启用时报错 |
| `import_db_schema` | execute | 选择表、目标目录、同名策略（update/skip/copy） |

- 工具名保持无 `apipost_` / `openpost_` 前缀，与现有 30 个工具一致。
- 工具表与设置页自动通过 `listToolInfos()` 展示。
- MCP 返回模型引用时使用 `openpost://model/<id>`；不返回数据库凭据。

## 6. UI

### 6.1 页面结构

`/schemas` 替换占位页，采用**页内本地标签栏**（不改全局 target 标签 store）：

- 顶部标签：`数据字典`、`数据库管理`、`全部模型`、具体模型（打开后新增）；`+` 新建菜单；`...` 溢出菜单。
- 左侧树：
  - 搜索框 `模型名/目录` + `+`
  - `数据字典`
  - `数据库管理`
  - `数据模型`（刷新/排序/折叠）
    - `全部模型`
  - 底部虚线 `+ 新建`：新建数据模型 / 新建模型目录 / 新建数据字段 / 新建数据库连接
- 无标签时的主区空态：三张入口卡片（数据字典管理 / 新建数据模型 / 数据库管理）。

标签关闭时若有未保存模型，弹确认；标签状态仅存在于字典页内。

### 6.2 数据字典页

- 子标签：`自定义` / `系统内置`。
- 顶部：搜索 `搜索参数名称或参数描述`；系统内置页右侧开关 `开启系统内置描述`（写 `project.is_describe_library`）。
- 表格列：参数名称（含类型徽标）/ 参数描述；自定义行悬停显示编辑、删除。
- 分页 10 条/页，显示总数。
- 新建/编辑弹窗：参数名称、类型、描述、备注、默认值。
- 本轮不做截图中的“保存临时数据”“导入”。

### 6.3 数据库管理页

- 表格列：名称 / 数据库类型 / 说明 / 操作；右上 `新建`。
- 连接弹窗：
  - 名称、说明、数据库类型（仅 MySQL）
  - 左侧仅 `默认配置`（不显示默认环境）
  - 标签 `常规` / `SSH`
  - 常规：数据库地址、端口（3306）、用户名、密码（可切换可见）、数据库名
  - SSH：启用开关、host、port（22）、用户名、密码、认证方式（密码/私钥/密码+私钥）、私钥、passphrase
  - 底部：`测试连接`、取消、确定
  - 安全提示文案沿用截图：用户名/密码/私钥不同步给团队，每位成员手动设置
- 测试连接只走直连；SSH 启用时返回“后续支持”提示。
- 导入流程：
  1. 选择连接 → 测试并读取表清单
  2. 勾选表、选择目标模型目录
  3. 同名策略：更新 / 跳过 / 副本（可对全部应用）
  4. 每表生成一个模型；表名 → 模型名，表注释 → 模型描述，列注释 → 字段描述
- 类型映射：
  - `tinyint(1)` → `boolean`
  - `tinyint/smallint/mediumint/int` → `integer`
  - `bigint` → `integer`（备注精度风险）
  - `decimal/numeric/float/double` → `number`
  - `date/time/datetime/timestamp/char/varchar/text/enum/set` → `string`
  - `json` → `object`
  - `binary/blob` → `string`
  - `IS_NULLABLE = YES` → 不加 `required`；否则加入 `required`
  - `COLUMN_DEFAULT` → `default`；`COLUMN_COMMENT` → `description`

### 6.4 全部模型页

- 顶部：搜索 `模型名称/别名`、`筛选`、列设置齿轮。
- 列：名称、别名、创建人、创建时间、最后修改人、修改时间、目录；本地应用显示当前系统用户名或“本地”。
- 列设置：显示/隐藏字段、字段搜索、拖拽排序（对齐截图）。
- 空态插画 + “暂无数据”。
- 左侧树拖拽排序/移动；右键菜单：编辑、复制、移动至、删除。

### 6.5 模型编辑器

标签内布局：

- 顶部：模型名称输入（占位“输入模型名称，建议使用代码模型名称或其同义词”）、描述输入、`删除`、`保存`。
- 工具栏：`Raw编辑` / `预览` / `生成代码`（禁用，标“后续支持”）/ `智能导入`（禁用，标“后续支持”）。
- 数据结构表（可视化）：
  - 根节点行：类型 `object`、必填/可空、描述
  - 字段行：字段名、类型选择、必填（*）、可空（N）、默认值、枚举、描述、`引用模型`、Mock 列（禁用占位）
  - 支持添加子节点、相邻节点、删除、展开/折叠；数组字段可编辑 `items`
  - 引用模型：选择后该字段存 `$ref`；循环引用在保存/预览时提示
- Raw 编辑：JSON 文本域 + 结构校验；切回可视化需通过校验。
- 预览：按当前 schema 生成示例 JSON（与发送时同一算法）。
- 关闭未保存标签时确认。

## 7. API 联动

### 7.1 请求 Body

- 仅 `raw` / `json` 模式显示 `引用模型`。
- 选择模型后：
  - 显示模型名徽标与实时生成预览（只读）
  - `body.model_id` 保存引用；`body.raw` 保存最近生成结果
  - 发送时主进程重新生成，忽略手改的 `raw`
- 用户点“编辑”：
  - 提示“编辑将解除模型引用”，确认后清除 `model_id`，`raw` 保留当前生成内容可编辑
- `解除引用` 直接清除 `model_id`，保留 `raw`。

### 7.2 响应示例

- `响应示例` 标签工具栏新增 `引用模型`。
- 关联后实时生成示例 JSON（只读），保存到 `expect.model_id` 与 `raw`。
- 可解除；模型失效时显示红色“模型已删除”徽标与解除按钮。
- 实时响应保存为示例时，若已有模型引用，提示是否保留引用（默认保留引用，丢弃本次响应体）。

### 7.3 生成算法

```
generate(schema):
  1. 解析 $ref（openpost://model/<id>），seen 集合检测循环；超过深度 8 停止
  2. example 存在 → 返回
  3. default 存在 → 返回
  4. enum 非空 → 返回 enum[0]
  5. object → 按 x-schema-orders 排序属性，递归生成
  6. array → [generate(items)]
  7. integer/number → 0；boolean → false；string → ""；null → null
  8. 返回 { value, warnings }
```

循环引用、失效引用返回 `warnings`，UI 显示黄色提示但不阻断保存。

## 10. 待输入与风险

- 本机 MySQL 连接信息（验证阶段）。
- `mysql2` 新增依赖；worktree 首次运行需 `npm install`。
- 模型编辑器 UI 工作量大；优先保证截图中的结构与交互，Mock/生成代码/智能导入以禁用态占位。
- 现有全局标签栏是 target 专用；本轮使用页内标签，后续若统一全局标签需另立 ADR。
- 明文凭据只适用于本地单机；导出、分享、MCP 必须持续脱敏。
